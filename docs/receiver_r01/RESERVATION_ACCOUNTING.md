# 资源调度校正记录

初始调度器的源内作业计时按dataset/backbone/method区分，但它在未完成所有机制计时前，用当前最慢机制替代未测机制估算。固定WiSig残差CE容量对照约12秒/epoch，显著慢于轻量CNN；将此值外推至尚未计时的Shen机制会导致不适用的保守估算超过6GPUh。

校正只涉及资源调度：在GPU1独立执行已冻结矩阵中每种Shen机制的第一个搜索作业；与GPU0正在执行的残差CE校准互不重叠。初始调度器在残差首作业完成后按其未测替代估算暂停；保留该行政暂停记录。新的调度器从完整已完成作业账本继续，仅调度原矩阵尚未启动的作业，不重新执行任何拟合、不增加候选、不换seed、不改数据/目标/epoch/LR。

所有机制均完成真实计时后，按各自实测速度重新估计；正式WiSig的14源RX相对内层10台显式乘1.4，Shen五台相对四台乘1.25，再加50%余量及300秒评价预留。若此完整矩阵仍超6GPUh则申请预算，不因结果挑选作业。本校正不增加6小时上限，也不使用评估RX标签。

较慢的正式容量控制在原矩阵中需100epoch；其资源超时按自身计时×2加60秒（至少1800秒），仍由全局6GPUh严格约束。它不是额外训练或延长100epoch。原注册、初始调度器及源代码seal保持原样，新的两个调度脚本独立保存。`initial_dispatcher_estimate_halt.json`、`shen_calibration_execution.json`和`method_specific_budget.json`公开这次管理层面的调整。

新调度器在每个stage内按上述事前时间估计降序调度独立作业，以减少空闲等待；作业顺序不依赖分类评价结果。所有formal作业仍等待全部源内搜索和选择冻结。

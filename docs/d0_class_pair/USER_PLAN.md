## 三、我现在最推荐的通用研究问题

第二篇论文优先候选 · 尚未证实的新问题

## 跨接收机泛化中的类别判别结构破坏

Class-Pair Discriminability under Receiver Shift

核心问题是：

> 现有 RFFI 方法为了抑制接收机差异，通常优化总体身份可分性或域不变性，但能否保证不同发射机之间的关键判别关系在未知接收机上仍然成立？

例如在训练接收机上：

\\[ \text{TX36 与 TX40 明显可分} \\]

而换成另一个接收机后，两者可能在模型的表示空间中十分接近，甚至发生类别混淆。

这与普通的“跨 RX Accuracy 下降”不一样。

我们要研究的是具体哪些类别之间的判别关系遭到破坏，这种破坏能否从源接收机上提前识别并在训练过程中降低。

问题的直观含义（示意，不代表真实特征分布）

源接收机

两类有清晰判别间隔

未知接收机

两类判别关系发生破坏

### 为什么这比前面的思路更值得试？

因为它符合我们现在真正需要的条件。

第一，有实际证据。 G1 和 P2-A 中存在类别级负迁移，不是凭空构造的异常。

第二，不依赖特殊硬件机制。 不需要真实同步起点、OOB 因果归因、连续采集时间，也不需要目标 RX 标签。

第三，可以在不同数据集上验证。 同样的类别判别问题可能出现在 LoRa、WiFi 或其他无线信号分类任务中，而不必强制使用相同的 STFT 前端。

第四，与已经失败的方法不同。 EISR 在训练完成后选择 Full/Strict 专家；新问题关注的是模型训练过程中能否保护跨接收机类别间的判别关系。G2-0 的频带评分失败也没有直接否定它。

不过，研究风险也很明确。

监督对比学习、Triplet Loss、ArcFace、类别条件域对齐以及基于 Wasserstein 的表示对齐都已经存在。2026 年 ICC 甚至有专门结合监督对比学习与 Wasserstein barycenter 的接收机无关 RFFI 工作。

[image](https://www.google.com/s2/favicons?domain=https://dblp.dagstuhl.de\&sz=32)

dblp.dagstuhl.de



所以普通地加一个 Contrastive Loss 或 Margin Loss 没有足够创新性。

我们真正要核查的是：现有方法是否主要改善整体特征几何，却仍不能稳定保护最容易在不同接收机之间发生混淆的类别对。

如果答案是肯定的，才可能形成具体的新方法。

## 四、如果问题成立，算法可以沿着什么机制设计？

先说明：以下是有条件的算法构想，不是现在就让 Codex 实现。

设模型输出每个类别的 logits：

\\[ z(x)=[z_1(x),\ldots,z_C(x)] \\]

对于真实类别 \\(i\\) 和另一个类别 \\(j\\)，定义判别间隔：

\\[ m\_{i,j}(x)=z_i(x)-z_j(x) \\]

如果 \\(m\_{i,j}(x)>0\\)，说明模型更倾向正确类别 \\(i\\)，而不是错误类别 \\(j\\)。

接下来我们可以针对每个源接收机 \\(r\\) 计算：

\\[ M\_{i,j}^{(r)} = \mathbb E[m\_{i,j}(x)\mid y=i,r] \\]

它描述 TX \\(i\\) 相对于 TX \\(j\\) 的判别间隔，在不同源接收机上如何变化。

我们真正关心的不是让所有类别间隔无限增大，而是：

在一些接收机上非常容易混淆的类别对，能否在训练中得到更有针对性的保护，同时不破坏其他类别的识别？

一个可能的思路是让分类器对源域内稳定暴露的困难类别对，优化跨接收机最差判别间隔。

但这里有两个严肃问题：

1. 源 RX 上的困难类别对，是否能够预测新 RX 上的困难类别对？
2. 即使能够预测，普通监督对比、类别均衡交叉熵、Group DRO 是否已经足够解决？

如果第一个问题不成立，不能开始开发该机制。如果第二个问题显示已有方法已足够，同样不能将它作为新论文贡献。

这是我们以前经常跳过的两个关口。

### D0：类别判别关系审计

只利用已经归档的预测，在十台源 RX 上分析：

| 分析               | 需要回答的问题                 |
| ---------------- | ----------------------- |
| 逐 RX 混淆矩阵        | 哪些类别对反复互相混淆？            |

尤其要避免只分析 TX36，因为我们已经在开发 RX 上观察过这个异常。

十个类别对应 45 个无序类别对；如果区分 TX \\(i\\) 被错误识别为 TX \\(j\\) 的方向，则有 90 个有向类别对。

现有预测每个 RX×TX 有 200 个包，可以完成这些描述性诊断，但统计时仍应把接收机视为主要分组，不把大量 packet 当成独立硬件环境。

### D0 的停止条件

下面几种情况都应停止：

- 类别混淆主要是某一个 seed 或某一台 RX 的偶然现象；
- 源 RX 的类别对关系完全不能提示被留出 RX 的错误结构；
- 类别级问题在合理的强基线下几乎消失；
- 现有 Margin/Contrastive/Group DRO 已经能够充分解释或解决。

只有证实存在可重复的剩余缺口，才批准训练新方法。

## 九、最后还有一项必须改变的研究习惯

之前我们已经做得很好的一点，是每个实验都预登记、留存失败 seed、独立复核、遵守数据边界。

但有一个地方需要改变：

不要把实验预登记变成“必须先证明某个想法很强，才能允许继续研究”的无限循环。

VIRP、EISR 这样的具体方法失败，说明对应方法不行；P0、C0 缺少真值，说明数据不能回答对应问题。这些结论都正确。

但是如果某个通用问题有充分的理论依据、已有论文存在明确的机制限制，那么在经过低成本审计之后，适当批准少量 GPU 训练是合理的。研究不可能全部在 CPU 审计阶段完成。

我建议今后采用两个不同标准：

- 问题验证： 只判断问题是否真实、重要且没有被现有方法充分解决。
- 算法验证： 允许一次小规模、明确预算的实验来测试新机制，失败就记录原因，而不是无限调参。

对第二篇而言，我现在最看好的研究主线可以概括为：

现有跨接收机方法追求整体鲁棒性，但怎样在未知接收机上保留具体发射机之间的关键判别关系，并避免少数类别被鲁棒化过程牺牲？

这不是已经找到的、保证可发表的创新点。IB-RFF、监督对比学习和类条件对齐都是直接竞争者，必须认真排查。

但是相比继续给 Shen 加新频带、继续修复一个 Gate，或者在没有真实起点的 IQ 上制造同步问题，这条路线具备更清晰的科研逻辑、更低的首轮验证成本，也不依赖 OSU。

我的建议是：先执行一次 D0 文献与类别判别结构审计。若能证实这个缺口，再围绕它做第二篇真正独立的算法方法，而不是继续沿用旧 RF-HSTU 的模块组合。

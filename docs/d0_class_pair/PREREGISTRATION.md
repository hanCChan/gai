# D0 冻结评价与边界

此文档与 registration.json、metrics.py、audit_d0_class_pair.py 在首次读取归档分数前一起封存。仅使用十台源 RX 的既有 Full/Strict 预测；不读取波形、OSU、四台开发 RX、六台历史锁定 RX，不训练、不推理、不下载数据。完成 D0 后停止。

所有 90 个有向类别对均计算真实误识别方向、排序违反率以及 margin 的均值、中位数、5%分位；45 个无序对按方向均衡汇总。margin 同时报原始与逐包中心化 RMS 归一化值。零尺度包全部间隔为零，归一化分母置 1。原始 margin 的跨 CNN 比较受尺度影响。

Full/Strict 同一 RX 必须行号、标签完全相同并对应 G1 缓存索引；200 包/类别。四模型源训练 RX 与评价 RX 不重叠，checkpoint、配置和缓存 SHA 核对；模型只哈希，不加载。分别训练的 CNN、scaler、前端共同变化，因此不能把差值归因为域对齐或身份信息因果损失。

主预测评价在相同 CNN 的五台评价 RX 内留一：其余四台形成 90 对混淆风险均值，预测被留出的 RX。对比仅源类别错误率、源类别错误率×错误去向分布、均匀预算。风险 profile 不用 probe 标签或分数；probe 标签仅用于最终评估。Spearman 使用平均 tied ranks；常量时无定义，不记为 0。固定 10 对检索错误质量，边界 ties 分摊预算。增加不同硬件参考控制与跨 CNN 迁移，后者明确受不同模型混杂。评价是已用过的源池内部诊断，不是独立新硬件验证。

RX 等权，不把包数或 90 对当作独立硬件重复，不报包级显著性。分别报告两折与硬件类型；七台 RTL 和三种单例硬件不能提供全面硬件族验证。只有一个 archived seed，不能判断跨 seed 可重复性。

冻结的描述性 screen：Strict 平均 accuracy 提升，并且有同一损害方向 Δ混淆率>0 在两折均出现；每个 method×fold cell 的 pairwise LORO 中位 Spearman 和 top10 capture 超均匀增益均为正。另报 pairwise 超 factorized 对照的增益，不把一般类别难度当作 pairwise 机制证据。第一个或第二个 screen 不通过，停止当前机制；通过也只是有限支持，不等于未被强方法解决。缺失强方法预测必须记 UNKNOWN。只允许提出有条件的基线验证预算草案，执行须另行批准，不能自动研发算法。

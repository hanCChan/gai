# 第二篇 LoRa 论文：G1-Shen 最新结果复盘与下一步决策

这次实验比 P2-A/A7 前进了一大步，因为你们已经从两台接收机各自训练、跨日期测试，转向了10 台源接收机联合训练、4 台开发接收机迁移评估。

现阶段可以支持的结论： 在这套固定源域训练和开发评估协议中，Strict-IB CIS 比 Full CIS 表现更好，而且四台开发接收机的三 seed 均值全部为正。

这意味着我们不必再把研究动机局限于“RTL-6 的设备34异常”。

但这还不是新算法贡献，也不是严格 IB 普遍有效的证明。

尤其值得肯定的是：你们没有因为结果变好就恢复局部 Notch 扫描、目标域调参或旧的 P2-B/P3。这样才能保留后续 OSU 结果作为真实的反证机会。

我现在更倾向将研究问题暂定为：

> 完整频谱信息在部分训练环境中具有判别能力，但会诱导模型学习不够稳健的特征依赖。严格频谱限制可能缓解这种问题，却存在接收机、表征和优化条件依赖。能否识别并控制这种依赖，是下一阶段需要验证的问题。

注意，“诱导了不稳健的特征依赖”目前仍是机制假设；已证明的是模型之间的预测性能差异。

这支持三个判断。

判断一：改善已经跨越多种接收机。 尤其 B200-1、N210-1、RTL-4 三台接收机，三个 seed 全部为正。相较于之前只研究 RTL-6，证据范围明显扩大。

判断二：模型随机性仍然不可忽视。 同一个训练 seed 在不同开发接收机上共享同一套模型权重，所以这 12 个比较不是 12 次完全独立实验。不能把 11/12 直接解释为某种统计显著性概率。

判断三：RTL-8 是下一阶段非常重要的反例。 它并非整体失败，但同一个方法有一次明显负迁移。如果未来要提出通用方法，我们需要解释这种风险，而不是只报告均值。

还有一个细节：四个开发接收机的平均提升，不能当作四类硬件完全独立的统计样本。特别是 RTL-4、RTL-8 属于同一硬件类型，B200 与 B200-mini 也存在芯片层面的相似性。

因此，现阶段最严谨的表述是：

> Strict-IB CIS 在当前四个开发接收机上具有一致的均值优势，但存在显著的模型初始化敏感性和个别接收机负迁移。

## 三、这次最值得优先处理的问题，其实是优化稳定性

你提供的 IQ 结果让我认为，下一阶段不能急于把 Full 与 Strict 的差异解释为频谱信息质量差异。

### 3.1 Strict IQ 发生了真正的训练塌缩

两个 seed 出现：

- 训练约 10 类随机水平；
- loss 约为 \\(\log 10\\)；
- 128 维 head embedding 全零；
- 输出几乎是常数。

这不是通常意义的“泛化不好”，而是网络没有成功学习分类任务。

可能涉及 ReLU 死激活、梯度传播、BatchNorm、学习率或网络训练动力学。你们已经检查了特征全零，但仅凭这个现象还不能确定最早的根因。

因此：

不能把这两个 Strict IQ 模型的失败归因为严格 IB 删除了发射机信息。

如果表示本身缺乏足够的信息，模型也可能正常优化，只是在训练集上无法很好分类；而现在连源训练都没有学起来。

### 3.2 Full IQ 则是另一类失败

Full IQ 的 seed20261014：

| 指标        | Accuracy |
| --------- | -------- |
| 源训练       | 约 94.66% |
| 四开发 RX 平均 | 32.79%   |

源训练与开发表现相差约 61.87 个百分点。

它没有观察到同类全零 embedding 现象。

这更接近源域拟合成功、跨域表现严重下降的情况，但同样不能立即认定是模型学到了 OOB 捷径。

还可能涉及 BatchNorm 统计、不同 RX 输入幅度或分布、学习到的接收机相关模式、训练样本不足等因素。

两个失败需要分别诊断：

| 失败类型             | 主要问题          | 优先检查                  |
| ---------------- | ------------- | --------------------- |
| Strict IQ        | 优化无法学起来       | 梯度、激活、BN、训练曲线         |
| Full IQ          | 源训练高、目标性能低    | 域偏移、BN 统计、混淆结构        |
| RTL-8 Strict CIS | 某个 seed 发生负迁移 | 源域拟合、目标错误类别、模型 margin |

我建议在本轮 G1 联合结果完成之前，不再修改这 24 个 OSU 正式训练任务。

之后单独安排优化诊断，而且 Full/Strict 必须使用对称的修复与搜索预算。

### 3.3 当前 Full CIS 与 Strict CIS 的比较是否公平？

作为两套固定训练流程的开发性能比较，基本成立；作为纯粹删除 OOB 的因果实验，还不成立。

因为 Full CIS 和 Strict CIS 的最终训练 epoch 分别是 16 和 19。

这不是程序错误：它们根据源 RX CV 分别选出了训练策略，且没有使用目标开发 RX 选择 epoch。

但是输入变换、独立训练 scaler、优化轨迹以及训练 epoch 同时不同。

因此当前实验能够说明：

> 在公平的源域选择规则下，Strict-CIS 流程的开发性能更好。

还不能证明：

> 唯一因为删除了不稳定的 OOB 信息，所以性能提高。

这个区别会直接决定审稿时的因果论证是否站得住。

## 四、20,000 包训练预算也是后续必须补充的限制

你们每类、每源 RX 固定 200 包：

\\[ 10\text{ RX}\times10\text{ TX}\times200 =20,000\text{ packets} \\]

这只相当于此前每台源接收机约 8000 包、十台合计 80,000 包的四分之一。

当前比较在相同受限预算下进行，因此不能说不公平。

但论文最终必须回答：

Strict CIS 的优势在更充足训练数据下是否仍然存在？

这是一个有意义的研究问题。

可能出现两种情况：

如果增加源域训练包数后 Full CIS 大幅追上 Strict CIS，说明当前收益可能部分来自有限样本下的归纳偏置或正则化效应。

如果增加数据之后 Full CIS 仍明显落后，才更有理由进一步研究完整频谱的环境敏感特征依赖。

我建议最终做一组源训练预算敏感性实验，但不需要现在执行。

| 每类每 RX 训练包 | 总源训练包  | 角色     |
| ---------- | ------ | ------ |
| 200        | 20,000 | 当前已完成  |
| 400        | 40,000 | 中等预算验证 |
| 800        | 80,000 | 较大预算确认 |

只有当 OSU 结果支持继续研究后，再对 Full/Strict CIS 进行这个对称实验，并保持源域模型选择规则冻结。

## 五、G1-OSU：已经冻结的24次实验应该怎样解读？

目前 OSU 计划是：

\\[ 2\text{ transfer directions} \times4\text{ models} \times3\text{ seeds} =24\text{ runs} \\]

这套方案可以提供重要的跨数据集实证。

但是有一个必须严格保留的边界：

OSU 每个方向只有一台源接收机，因此不能估计训练源接收机之间的稳定性方差。

这一点你们已经处理正确。没有源域跨 RX 方差，就应该写缺失，而不是填零。

OSU 当前的任务应当是 G1 外部复现，而不是 G2 可靠性指标验证。

### OSU 最重要的四种结果

| OSU Full/Strict CIS 结果 | 可以得出的判断                 | 下一步           |
| ---------------------- | ----------------------- | ------------- |
| 两个方向多 seed 均正收益        | 频谱限制现象具有较强外部复现证据        | 进入 G2         |
| 一个方向正，一个方向负            | 效益具有明显方向/接收机依赖          | 优先研究条件性，不宣称通用 |
| 两个方向普遍负收益              | 固定 Strict-IB 规则的普适主张不成立 | 停止包装通用过滤方法    |
| 大量模型没有成功优化             | 无法干净判断频谱效果              | 先解决统一优化问题     |

其中最后一种需要特别强调。

OSU 是 25 类任务，随机水平约为 4%，与 Shen 的十类随机水平不同。

如果某些模型在 OSU 上出现训练塌缩，不能将其低分当作跨数据集频谱方法失败的纯证据。

要如实报告失败，同时区分“模型无法学习源任务”和“模型可以学习源任务但无法泛化”。

### OSU 联合报告必须包含的结果表

| 方向        | Full CIS | Strict CIS | 配对 ΔF1 | 训练是否正常 |
| --------- | -------- | ---------- | ------ | ------ |
| RX1 → RX2 | 待完成      | 待完成        | 待完成    | 待核查    |
| RX2 → RX1 | 待完成      | 待完成        | 待完成    | 待核查    |

最终还必须给出逐 seed、逐 TX 召回、实际窗口数量、训练曲线和失败日志。

由于两个方向使用相同两台接收机，只是训练和测试角色交换，不能把它们宣称为两个完全独立的硬件环境样本。

另外，当前只有一个源 RX，不能用目标 RX 表现去调整频带、归一化、窗口位置或训练 epoch，否则 OSU 的独立验证价值就会被削弱。

## 六、接下来最重要的科研问题：为什么 Strict CIS 有收益？

现在真正值得追问的是：

> 是否存在某类频谱信息，能帮助模型拟合训练数据，却在跨接收机时增加错误？

要回答它，我会把 G2 拆成两个问题，而不是直接设计新损失函数。

### G2-A：这种风险能否被观察到？

首先利用 Shen 的 10 台源接收机做 Leave-One-Receiver-Out。

每次选 9 台源 RX 训练或计算特征统计，剩下 1 台只用于检验。

比较 Full CIS、Strict CIS 和少量预先固定的频谱表征。

这里的评估单位是真正被留出的接收机，而不是随机 packet。

在这一步，先研究两类量：

\\[ D_b=\text{频带 }b\text{ 对发射机的辨识性} \\]

\\[ V_b=\text{同一发射机在不同源 RX 的表征变化} \\]

目前的八等宽频带统计使用 log-PSD 类中心，而且 source 重代入准确率有偏，不能直接拿来声称 G2 成立。

它们只能作为探索性描述。

更进一步，需要在不使用留出 RX 信息的情况下，计算频带稳定性指标，验证其与该 RX 真实分类误差之间的关系。

这里应该检查的是预测有效性，例如频带可靠性排序与留出 RX 表现的排序相关性，而不只是画出漂亮的频谱图。

### G2-B：这种风险能否被源域预测？

这是可能形成方法创新的真正门槛。

假设在训练源接收机中，某个频带看起来极容易区分设备，但它的表征在不同源 RX 之间变化很大。

如果该频带在被留出的 RX 上也确实容易失败，我们才有理由设计一个模型，降低对这种频带的依赖。

反之，如果所谓稳定性评分与目标表现没有关系，那么再添加可靠性损失也没有依据。

这里还需要一个强负对照：

仅使用源域分类准确率来选择频带。

如果简单的源域准确率就能预测目标性能，我们新提出的复杂可靠性指标就没有充分必要性。

若 G2 通过，再与 GRL、对比学习、FAN/HSIC 等方法公平比较，检验这种新增机制到底是否优于已有方法。

## 八、目前最值得形成的论文主张是什么？

我不建议现在把“Strict-IB CIS”直接命名为新算法。

严格频带限制本身很简单，也存在参数和信号体制依赖。即使 Shen、OSU 均有效，它更可能先构成一个强基线或动机发现，而不是完整的方法贡献。

我更看重的是下面这个方向：

Receiver-Conditioned Spectral Reliability for Robust RF Fingerprinting

暂定中文含义：面向稳健射频指纹识别的接收机条件频谱可靠性建模。

但名称中的 Receiver-Conditioned 也要谨慎：如果推理时不使用接收机身份，最终应突出的是训练源域建模与未知接收机泛化，而不能暗示目标接收机标签是已知的。

这条路线需要先证明：

- 频谱判别性与跨接收机可靠性不是同一个量；
- 这种差异可以在训练源域中被估计；
- 估计结果可以预测未见域上的风险；
- 利用这种预测能够实际改善识别，而且优于简单过滤与已有方法。

只有完成这条逻辑链，论文才能从“尝试一种频谱处理技巧”上升到“提出一种具有机制依据的泛化学习方法”。

## 九、最终建议

继续把 Strict-IB CIS 作为最重要的候选基线。

Shen 四开发 RX 的 +13.03 pp 是有价值的证据，尤其多个 seed 与接收机均有积极趋势。

不要把 Full/Strict 差异直接解释成不可靠 OOB 被成功去除。

模型 epoch、scaler、输入优化几何以及严重的 IQ 优化失败都需要分离。

保留 OSU 的独立反证价值。

不在看到目标结果后改动当前冻结的训练方案。OSU 不支持时，不强行包装成普适频带方法。

下一次真正的方法突破应当来自 G2，而不是增加网络复杂度。

如果训练源的频谱稳定性能够预测未见 RX 失败，那么才有充足依据研究可靠性约束或条件性频谱选择。

就目前来说，我认为第二篇论文的方向比 P2-A 结束时清楚得多：

我们已经观察到一个跨多个开发接收机的强表征差异，但尚未发现它背后的普适机制。

下一步不应该把这 13 个百分点直接写成创新成果，而应该用 OSU 复现、源接收机留一预测、优化混杂控制，逐层判断：

到底是某种简单的频谱过滤技巧偶然占优，还是存在一个可以被建模、可以预测、并能够指导新算法设计的跨接收机可靠性问题。

这个判断做出来之后，才值得正式决定新方法以及最终论文结构。

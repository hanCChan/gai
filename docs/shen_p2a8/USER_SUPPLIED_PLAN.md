# LoRa RF-HSTU/OOB 第二篇论文：P2-A 实验复盘与后续研究方案

审查版本： `hanCChan/gai` · `experiment/shen-p2a` · 提交 `1106c43` 研究阶段： P1 → P2-A 108 次训练 → A7 16 次补充实验 → 方法方向重新评估

## 一、先给出目前最重要的研究结论

我已经通过 GitHub 连接读取了新提交的总报告、A5 分支诊断和 A7 补充报告。它们共同指向一个很重要的判断：

目前最值得深入的方向，不是继续设计更复杂的 OOB 融合门控，而是研究为什么某些频谱成分对接收机或跨日期变化敏感，以及如何保留发射机身份信息、抑制这些不稳定因素。

这实际上让论文的科学问题比原来更清楚了。

原来的核心设想是：

> IB 与 OOB 各自包含发射机特征，通过 HSTU、Cross-Attention 或可靠性门控融合，提高跨接收机的设备识别性能。

但 P2-A 的实验至少暴露了三个问题：

- OOB 分类能力强，不等于它能提供稳定、互补、跨接收机的身份信息。
- 双分支网络准确率提高，不等于网络实际融合了两种信息。
- 完整频谱不一定优于受限频谱；对 RTL 接收机，删除部分频谱信息后，特定开发任务反而显著改善。

尤其第三点，是后续值得研究的线索。

目前各技术方向的判断

基于已取得的 Day2 开发证据

严格 IB 频谱限制

强烈值得继续验证

IB+IB 容量匹配基线

有效的正向对照

OOB 频带独立诊断

有效的机制证据

Full/IB 优化稳定性研究

仍需解决混杂因素

IB+OOB 简单门控融合

预登记门槛失败

横条表示后续研究的相对优先级判断，不是统计显著性、模型准确率或论文成功概率。

因此，我支持你们没有启动 P2-B/P3 的决定。现在直接训练 HSTU、Cross-Attention 和 GRL，可能产生更多数字，却仍然回答不了现阶段最关键的因果与方法问题。

不过也必须强调：A7 的严格 IB 改善发生在单个开发接收机的 Day2 数据上，另一台 N210 接收机反而出现性能下降。因此，尚不能把“去除 OOB 就能提高鲁棒性”写成论文结论。

下面进一步区分：哪些矩阵验证有效、哪些技术路线应停止、哪些结果可能存在问题，以及怎样重新安排后续实验。

## 二、逐项复盘：原 P2-A 实验矩阵到底哪些有效？

我将这次实验按 A1–A7 重新分类。这里的“有效”不是指准确率最高，而是指实验有没有回答原先提出的科学问题。

### 2.2 A1：CIS 优于 Spec，但不能说它解决了跨接收机问题

相同模型参数量 658,314 · Day2 Accuracy

Spec

0%25%50%75%100%N210 完整 STFTRTL 完整 STFTN210 严格 IBRTL 严格 IB

两种表征使用相同 CNN 架构和 STFT 几何；数值为三 seed 均值。

在 N210 上，CIS 的改善较小，因为普通 Spec 已经接近 99%。

在 RTL 上，CIS 从 67.43% 提升至 73.52%，改善了 6.09 个百分点。不过设备34仍然是 0% Recall。

这说明两件事：

首先，CIS 的相邻时间帧谱比值有一定价值，不是随便替换成普通谱图就可以取得相同效果。

其次，CIS 并没有天然消除所有跨日期分布偏移。

后续应保留 CIS 作为强表征基线，不能简单回退到普通 Spec CNN。

但也没有理由把 CIS 本身写成论文创新，因为它来自已有研究。真正值得研究的是：CIS 为什么在 RTL 的某些频率区域依然失败，以及严格频带限制为什么能改善它。

### 2.3 A2：减小参数量不能解决设备34异常

这次轻量 CNN 约 65.8 万参数，作者原 CNN 约 1344 万参数。

在 RTL 原始 CIS 的配对比较中，轻量模型相对作者模型三个 seed 分别下降：

- 3.10 个百分点
- 2.70 个百分点
- 7.45 个百分点

设备34问题也没有解决。

这里已经可以排除一个过于简单的解释：

> 设备34识别失败是由于作者网络参数太多，过拟合了训练数据。

至少目前没有数据支持它是主要原因。

但也不能反过来说“大模型必然优于小模型”，因为 rank16 的线性头不只是减小参数量，还改变了网络可以表达的特征空间。

下一阶段不需要为了设备34继续做大规模宽度搜索。 应优先研究输入信息、频谱位置和接收机变化。

### 2.4 A4：近带外值得研究，但它不是已经证明的可靠 OOB 指纹

这组实验非常重要。

| 频带       | N210 Accuracy | RTL Accuracy |
| -------- | ------------- | ------------ |
| 假定 IB 频带 | 68.67%        | 68.52%       |
| Near OOB | 86.30%        | 89.27%       |
| Mid OOB  | 47.53%        | 28.92%       |
| Far OOB  | 56.02%        | 24.22%       |
| All OOB  | 72.63%        | 87.22%       |

从实验上看，近带外比其他独立频带更容易分类，而且两个接收机上都成立。

这是一个值得追问的现象：

为什么假定信号带宽附近的频谱如此有辨识度？

目前至少有四种可能解释：

1. 存在发射机非理想性产生的有效频谱特征。
2. 有限长度 FFT、信号调制和频谱泄漏，使近带外仍包含与主信号相关的信息。
3. 近带外携带接收链路、滤波器或采集条件的特征。
4. 频带宽度、归一化和网络优化难度不同，使独立模型的结果不能直接解释为物理信息量排序。

特别注意：A4 是独立训练分类器，而 A7 是先限制原始 FFT，再重新生成 STFT 表征。

两者输入变换和模型都不同，因此：

> “Near OOB 分类效果好”和“删除假定 OOB 后 RTL STFT 效果更好”并不矛盾。

它们共同说明的是：频率内容如何表示、组合和归一化，会显著影响识别。

下一步需要把这两类实验放进完全统一的模型与归一化设置中比较。

## 三、A5 融合失败：比平均准确率更重要的是模型实际在用什么

这是我认为这次实验最应该停止的一条路线。

### 3.1 RTL 的结果已经足够明确

| RTL 模型        | Accuracy | Macro-F1 |
| ------------- | -------- | -------- |
| Single IB     | 88.50%   | 0.8842   |
| IB+IB Concat  | 93.83%   | 0.9378   |
| IB+IB Gate    | 93.92%   | 0.9391   |
| IB+OOB Concat | 82.50%   | 0.7945   |
| IB+OOB Gate   | 76.50%   | 0.7213   |

IB+IB 比 Single IB 好，说明额外参数量、双编码器结构、优化路径本身能够带来收益。

但添加 OOB 后，不仅没超过 IB+IB，甚至大幅下降。

特别是 Gate：

\\[ 76.50\\%-93.92\\%=-17.42\text{ pp} \\]

在这套模型与数据上，替换第二条 IB 分支为 OOB 分支是明显不利的。

### 3.2 N210 存在一点积极迹象，但不足以改变结论

N210 的 IB+OOB Gate 相对于 IB+IB Gate，三个 seed 均有小幅正收益：

\\[ +0.80,\quad +0.55,\quad +1.15\text{ pp} \\]

这不能忽略，它说明 OOB 输入对特定双分支结构并非总是有害。

然而，同一模型相对于 Single IB 的三个 seed 是：

\\[ +3.80,\quad -2.15,\quad -0.80\text{ pp} \\]

所以它没有满足你们提前登记的“双基线、三个 seed 同时严格领先”的门槛。

因此正确的结论是：

OOB 对某些结构可能存在局部效益，但没有证明稳定的、超越强 IB 基线的有效互补。

### 3.3 更大的问题：Gate 几乎完全退化为单分支

我检查了 `src/shen_p2a/models.py` 里的核心实现：

```
gate = torch.sigmoid(self.gate(combined))fused = (1 - gate) * main + gate * aux
```

这是典型的标量门控结构。

六个 IB+OOB Gate 的 `gate_mean` 都接近 1。

也就是说：

\\[ z\_{\text{fused}}\approx z\_{\text{OOB}} \\]

报告中六个模型的 OOB 辅支单独 logit 答对数量也与完整模型一致。

而进一步查看 [A5 逐设备分支贡献表](https://github.com/hanCChan/gai/blob/1106c43/reports/shen_p2a/2026-10-12_p2a_complete/A5_branch_diagnosis/per_device_branch_contributions.csv)，还发现一个重要现象：

即使是 IB+IB Gate，部分 N210 seed 的门控也会饱和到接近 0 或 1。

例如有一个 N210 seed 的 IB+IB Gate 均值约为 0.00000484，另一个 seed 则接近 0.99994。

这说明单分支退化不一定由 OOB 本身独立造成，门控架构和优化过程也存在问题。

不过，当前分支诊断是已训练分类器的代数拆分，并非真正重新训练单分支模型；Gate 本身仍由双支嵌入计算。因而它能支持“几乎只使用辅支”的数值解释，但不构成严格的因果消融。

我的决策：不要现在修改 Gate 加正则化，然后继续试图让它融合。

强行让 Gate 落在 0.5 附近，不代表信息互补，只可能让模型不得不使用有害信息。

正确顺序必须是：先证明 OOB 在未见接收机上存在独立的正向收益，再设计如何稳定利用它。

## 四、A7 是这次最有价值的发现，但需要重新解释

### 4.1 严格 IB 的收益不只来自设备34

这点是我查看 [A7 逐设备纠错表](https://github.com/hanCChan/gai/blob/1106c43/reports/shen_p2a/2026-10-12_p2a_complete/A7_followup/report/paired_per_device.csv) 后，认为非常值得深入的一点。

对 RTL 的 Strict-IB Spec，相对 Full-STFT Spec，汇总三个 seed 的设备级净纠错如下：

| 发射机标签 | 三 seed 总净纠错 | 对应平均 Recall 净变化 |
| ----- | ----------- | --------------- |
| TX32  | +495        | +82.50 pp       |
| TX33  | +425        | +70.83 pp       |
| TX34  | +486        | +81.00 pp       |
| TX39  | +100        | +16.67 pp       |

每个发射机每个 seed 有 200 包，因此一类发射机的三个 seed 共计 600 次预测。

这个结果意味着：

RTL 的完整 STFT 问题不是只有设备34这一个类别。TX32、TX33 同样存在严重的可修复误差。

这是比单一异常设备更有论文价值的问题。

因为它可能意味着完整 STFT 存在某种系统性的特征依赖，使部分发射机类别在 Day2 上发生大规模混淆。

下一步必须重点检查 TX32/33/34 的混淆关系，而不是继续只盯着 TX34。

建议形成三张图：

- Full-STFT 与 Strict-IB STFT 的完整混淆矩阵差异。
- TX32、33、34 在 Day1 与 Day2 的频谱分布对比。
- 这些类别在不同频带中的可分离性与跨日期变化。

如果能够证明某类不稳定频谱特征同时影响多个发射机，研究问题会更有普遍性。

### 4.2 A7 还存在三个重要混杂因素

第一，N210 的结果与 RTL 相反。

在 N210 上，Strict-IB Spec/CIS 分别比 Full-STFT 低约 4.35 和 3.49 个百分点（均值差）。

说明严格限制频谱可能删除了 N210 上有用的信息。

第二，归一化统计不同。

虽然两者都严格只使用 Day1 Train 计算均值和标准差，但 Full 和 Strict-IB 各自重新拟合了标量。

因此比较同时改变了频谱内容与输入统计分布。

第三，CIS 的学习率不一样。

RTL Strict-IB CIS 使用 `lr=0.001`，Full-STFT CIS 使用 `lr=0.0003`。

所以 RTL CIS 的 20 多个百分点收益不能全部归因于频谱限制。相比之下，RTL Spec 的三 seed 比较学习率相同，证据更干净，应作为下一阶段的首要研究对象。

### 4.3 目前最合理的机制假设

我建议把下一阶段的主假设写成：

> 对于某些接收机和采集条件，完整频谱表征包含与发射机标签相关、却缺乏跨环境稳定性的特征。模型可能利用这些特征取得训练集拟合，但在分布变化时发生系统性误分类。频谱限制能缓解这种依赖，但可能同时移除其他接收机上的有效身份信息。

这个假设比“RTL34的 OOB 有问题”更具有一般性，也更容易发展成方法。

但它仍然只是待验证假设。

## 五、代码和实验协议中需要优先处理的问题

审查范围包括提交版本的主要报告、预登记矩阵、频带与表征代码、训练入口、模型定义，以及相关的汇总和逐设备 CSV。

由于 GitHub 上没有原始 IQ、权重及完整逐包预测，本次能够审计公开的程序逻辑与统计证据，不能声称已独立重新运行全部 124 次训练或重新核算每条原始预测。

我建议按下面的优先级处理。

P0｜物理频率定义尚未核实

最高优先级

`src/shen_p2a/bands.py` 和 A7 缓存中的频谱投影，使用了 1 MHz 采样率与 125 kHz 带宽假设。

如果真实采集参数不同，那么 ±62.5 kHz 可能并不是实际意义上的信号带内，−101.6 kHz 的异常位置也不能作准确物理解释。

处理： 检查原数据采集脚本、硬件配置、HDF5 属性和原论文实验设置。无法核实时，论文只能使用“assumed nominal passband”，不能宣称真实发射机带内/带外因果机制。

P0｜Day2 已经被反复用于研究选择

最高优先级

P1、P2-A、A7 均已从 Day2 结果中获得研究信息；P2-A 又使用首个 seed 的 Day2 Macro-F1 筛选配置，并用同一 Day2 报告确认结果。

预登记与保存全部候选降低了选择性报告风险，但不能消除开发集反复使用造成的乐观偏差。

处理： 新增实验仅用于机制解释。最终模型冻结之前，把模型选择尽可能转移到训练接收机内部的分组验证，另设未参与方法开发的评估数据。

P1｜尚未分离频谱信息与优化影响

A6 的 Full/IB 存在 seed 胜负反转，而且选定配置中 Full 和 IB 的 WD 不同。A7 的部分表征又改变了学习率或 scaler。

处理： 对核心假设使用相同架构、同 LR/WD、同训练策略、同 seed 集、同样的数据与变换预算；另以独立消融测试 scaler 和优化影响。

P1｜20 台接收机没有研究史上的全新盲测集

已发表的旧 OOB 研究使用过六台原盲测接收机，其他14台也有使用记录。

处理： 将 10/4/6 明确称为“本轮训练/开发/锁定集合”。若要宣称真正独立外部验证，应新增未用于本研究方法选择的数据；只有测试时锁定仍可作为本轮冻结模型的确认集，不能夸大历史独立性。

P1｜未解决接收机与日期的混杂

目前主要是 Day1 训练、Day2 测试的同接收机实验，并没有证明跨接收机泛化。

处理： 把同接收机跨日期、同日期跨接收机、同时跨日期和接收机拆成不同的评估协议，按接收机类型分别报告。

还有两个工程细节值得关注。

其一，`src/shen_p2a/representations.py` 使用 128 点 boxcar STFT，而 A7 在此之前对 8192 点原始 FFT 进行频带投影。先做投影并不意味着后续 STFT 图上所有带外坐标严格为零，局部窗口仍会产生频谱泄漏。你们报告中已经正确注明了这一点；后续解释应保持这个边界。

其二，`runner.py` 的 A6 虽然跑满 30 epoch，但最终统计使用的是 30 epoch 内 Day2 Macro-F1 最好的 checkpoint，不等于最后一个 epoch 的模型。讨论“训练更久是否救回塌缩”时，需要同时观察固定 epoch 模型、best checkpoint 和早停反事实，不能混为一谈。

## 六、下一步究竟做什么？我建议改成三道连续决策关卡

与其立即执行 P2-B，不如新增一个较小的 P2-A8 机制隔离阶段。

阶段 M0：数据与物理信息审计

不训练 · 核对采集参数、异常类别和频谱位置

阶段 M1：受控频谱反事实

约 30 次新增训练 · 区分特征内容、位置、归一化与优化影响

阶段 M2：真正的跨接收机开发实验

多接收机联合训练 · 比较强 IB / CIS / GRL / 对比学习基线

阶段 M3：满足条件才开发新的方法

频带稳定性建模，或正式终止 OOB 融合路线

### 6.1 M0：先把数据和机制诊断做干净，不需要 GPU 大训练

我建议输出一份新的 `M0_DATA_AND_FREQUENCY_AUDIT.md`。

重点完成：

1. 明确采样率、信号带宽、SF、中心频率、接收机型号与固件；CFO/SNR 的字段单位及是否经过预处理。
2. 比较 TX32/33/34 在 RTL Day1 和 Day2 的每包频谱，特别是约 −101.6 kHz 的位置，同时检查正频率对称位置。
3. 对原始 IQ 检查能量分布、饱和、信号截断、包边界、噪声底、频偏与频谱平移。
4. 查验同一 TX 在不同接收机上是否出现相同变化；若无可靠同步采集，不能用包序号假定跨接收机一一配对。
5. 输出每个设备的 Train→Day2 频谱变化分布和类别间可分离性，不仅看平均特征图。

其中最关键的判据是：

如果 TX32/33/34 的失败对应具体频率位置的异常，但这种异常不普遍存在于其他发射机，就需要特别警惕数据采集或类别相关偏差；不能立即解释为一般性的接收机频谱失真。

### 6.2 M1：我建议的新增实验矩阵

统一使用 A1/A7 的轻量 Spec CNN 作为首轮机制模型。

第一部分测试的是“究竟应该删除哪些频率”。

| 候选表示                      | 想验证的假设              |
| ------------------------- | ------------------- |
| Full-STFT                 | 现有完整对照              |
| Strict-IB STFT            | 现有 A7               |
| 仅对 −101.6 kHz 附近做局部 Notch | 是否存在局部有害特征          |
| 正频率对称位置 Notch             | 是否是对称频带现象           |
| 等宽随机位置 Notch              | 是否只是删除一部分特征带来的正则化效应 |

这里 −101.6 kHz 是在看到 Day2 结果后选择的，因此新 Notch 对照仍应明确标记为探索性实验。频率区间宽度和随机对照规则要在运行前冻结，不能根据同一开发集继续调整后声称独立验证。

另外，所有 Notch 应在原始频域使用同一种投影方法，不能一组直接截断，一组使用不同的滤波器。

第二部分专门隔离归一化：

| 因素     | 条件                                                 |
| ------ | -------------------------------------------------- |
| 频谱输入   | Full / Strict-IB                                   |
| Scaler | 各表示独立的 Train-only scaler / 公共 Train-derived scaler |
| 模型     | 相同 CNN                                             |
| 优化     | 固定 LR、WD、epoch 策略                                  |
| Seed   | 20261012、13、14                                     |

这形成 2 接收机 × 2 频谱输入 × 2 归一化方案 × 3 seed = 24 个组合，其中当前已完成、完全匹配设置的 12 个组合可以作为已有对照，只需追加约 12 次训练。

局部 Notch 三种新处理 × 2 接收机 × 3 seed = 18 次训练。

合计新增约 30 次，而不是再盲目执行 100 多次。

四张 V100 的建议分工

| GPU    | 工作                     |
| ------ | ---------------------- |
| V100-0 | RTL 局部 Notch 与对照       |
| V100-1 | N210 对称 Notch 与对照      |
| V100-2 | Scaler 控制实验            |
| V100-3 | 混淆矩阵、频谱诊断与失败复核；空闲时分担训练 |

这只是推荐排程，不是已启动的任务。

### 6.3 M1 应当如何判断成功

我建议不以单一 Accuracy 排名作为成功标准，而是回答三个问题。

假设 H1：改善由少数特定频率引起。

如果 RTL 上局部 Notch 接近 Strict-IB 的收益，而等宽随机位置 Notch 无类似收益，则支持频率位置特异性。

如果所有 Notch 都改善，则更可能是删减特征或优化正则化效应。

假设 H2：收益不依赖于重新归一化。

如果使用公共 Train-derived scaler 时 Strict-IB 仍然改善，说明这部分收益不完全来自独立重新估计 scaler。

如果收益大幅消失，就必须重新解释 A7。

假设 H3：异常涉及多个类别，而非 TX34 独有。

要统计 TX32/33/34 的 Recall、误判去向、分类 margin、纠错和新增错误，避免高总体准确率掩盖某一类的损失。

只有这些机制被较好隔离后，才值得进入下一阶段。

## 七、M2：必须尽快开始跨接收机实验，但不要直接用它证明新方法

这一阶段是决定论文是否还能沿着“跨接收机 RFFI”发展的关键。

### 7.1 重新规范训练与开发集合

现有候选 10/4/6 可以继续作为本轮角色划分的基础，但需要经过历史审计后冻结。

建议采用：

| 数据角色       | 用途                      |
| ---------- | ----------------------- |
| 10 台训练接收机  | 多域联合训练、训练内分组验证          |
| 4 台开发接收机   | 已知历史使用的跨接收机开发评价         |
| 6 台本轮锁定接收机 | 方法冻结后的本轮确认评价，不宣称研究史全新盲测 |
| 额外独立数据     | 最终外部泛化验证                |

训练端必须避免将某一个接收机的 packet 随机划入训练、其余 packet 划入验证，却声称是“跨接收机”。

应该以接收机为分组单位，并记录同一物理发射机在各接收机上的对应关系。

另一个重要问题是 B200 和 N210 型号覆盖：当前 10 台候选训练接收机中没有与开发集 `b200_1`、`n210_1` 完全对应的同型号设备。它们涉及硬件类型外推，而 RTL 开发接收机更接近同类型不同实例的泛化。因此不能只汇总四个开发接收机的平均值。

### 7.2 第一批跨接收机基线矩阵

暂时不加入任何复杂新结构。

| 基线                | 主要目的             |
| ----------------- | ---------------- |
| Full IQ CNN       | 判断原始完整输入的跨接收机性能  |
| Strict IB IQ CNN  | 评估频谱限制收益         |
| Full-STFT CIS CNN | 强表征参考            |
| Strict-IB CIS CNN | 直接检验 A7 能否泛化     |
| CIS + GRL         | 检验接收机对抗特征学习      |
| CIS + 代表性对比学习     | 检验跨接收机的类内一致性     |
| 简单固定频带/频带加权       | 为后续自适应频带方法提供廉价基线 |

GRL 和对比学习不能直接使用当前单接收机 P2-A 数据训练后就宣称其跨接收机能力。它们需要多训练接收机，且采样策略应保证相同发射机的跨接收机正样本与错误负样本被正确处理。

模型选择最好先在 10 台训练接收机内部进行 Group-wise CV，避免继续在四台开发接收机上大规模调参。

### 7.3 推荐的评估维度

| 指标                       | 为什么必须有             |
| ------------------------ | ------------------ |
| 每 RX Accuracy / Macro-F1 | 防止某台接收机特别差         |
| 每 TX Recall / Macro-F1   | 防止重演 TX32/33/34 失败 |
| Worst-RX Accuracy        | 测量部署风险             |
| 跨 RX 均值及离散程度             | 衡量跨域变化             |
| 同 RX 跨日期结果               | 分离时间漂移             |
| 跨 RX 同日期结果               | 分离接收机影响            |
| Receiver probe accuracy  | 辅助观察是否保留接收机信息      |
| 参数量、吞吐与推理成本              | 判断方法实际代价           |

Receiver probe 需要控制发射机类别和类别不平衡。探针准确率低，也不能证明表征完全不含接收机信息。

三 seed 的均值和标准差只描述训练随机性；跨接收机的性能不确定性还取决于有多少真正独立的接收机、session 和采集环境。不要把 2000 个高度相关 packet 当作 2000 个独立环境。

### 7.4 我建议的阶段通过条件

这些是下一轮可以预登记的工程决策标准，并非现有实验已经证明的统计门槛。

- 核心方法相对最强的简单基线，在跨接收机平均 Macro-F1 上达到有实际意义的提升，例如至少 +0.03。
- 至少三个开发接收机上的趋势为正，且不能靠牺牲某一台接收机十几个百分点换取均值。
- 三个确认 seed 的方向基本一致，并报告完整失败 seed。
- TX32/33/34 的改善不是以其他类别严重退化为代价。
- 方法不能只在 RTL 成功而在另一类接收机明显失败，却仍声称通用的跨接收机稳健性。

如果这一阶段 Strict-IB、CIS、简单 GRL 或对比学习已经很好，而复杂融合没有收益，那么继续开发 OOB CrossAttention 的优先级应该更低。

## 八、真正能投论文的方法方向，现在有哪些选择？

这是你最关心的问题。

我认为研究发展路线可以分成三个方向，优先级已经与之前不同。

### 方向 A：发射机条件的频带稳定性建模

目前最值得验证的主方向

核心科学问题是：

> 哪些频带既能区分不同发射机，又能让同一发射机在不同接收机上保持稳定？

这比直接问“OOB 有没有用”更具体。

可以对第 \\(b\\) 个频带定义两个量。

类间可分性：

\\[ D\_{\text{between}}^{(b)} =\mathbb E\_{y_i\ne y_j}d(z_i^{(b)},z_j^{(b)}) \\]

同发射机跨接收机差异：

\\[ D\_{\text{within-RX}}^{(b)} =\mathbb E\_{\substack{y_i=y_j\\\r_i\ne r_j}} d(z_i^{(b)},z_j^{(b)}) \\]

构造一个简单的频带稳定性分数：

\\[ S_b= \frac{D\_{\text{between}}^{(b)}} {D\_{\text{within-RX}}^{(b)}+\epsilon} \\]

直观含义：

- 分子越大，不同发射机越容易区分。
- 分母越小，相同发射机换接收机后越稳定。
- 因此较高的 \\(S_b\\) 代表该频带可能更适合跨接收机识别。

这个分数只是一个研究原型。距离度量、采样条件、信道差异与表征坍缩均需要严格控制；不能把它直接当作已经验证的鲁棒性指标。

由此可以设计一个训练源域计算的频带加权基线：

\\[ z=\sum_b w_b z_b,\qquad w_b=\operatorname{Softmax}(S_b/\tau) \\]

如果固定权重证明有效，再考虑输入质量条件下的动态加权。

关键是：频带权重首先必须通过训练源接收机的跨域稳定性得到支持，而不是由 Day2 单一开发集准确率决定。

### 方向 B：Strict-IB CIS + 接收机不变学习

这是更务实的候选方法方向。

模型结构可以先很简单：

\\[ \text{Strict-IB CIS} \rightarrow \text{CNN Encoder} \rightarrow \text{TX Classifier} \\]

训练时加入 Receiver GRL 或跨接收机监督对比约束。

这一方向的优势在于你现在已经有强的 RTL 结果，而且参数量较小。

但它的论文新颖性风险也比较高：严格频带限制、CIS、GRL、对比学习都是已知技术。简单拼接通常不足以形成令人信服的方法贡献。

要发表，必须解释为什么这些组件组合起来解决了已知方法无法解决的特定问题，并在多个独立域上验证。

### 方向 C：保留 OOB 的条件性利用，而非强制双路融合

这条路线我建议暂时排在第三位。

只有在 M2 中发现：

- 某些 OOB 频带对未见接收机确实有额外收益；
- 简单融合存在负迁移；
- 能够用源域信息或输入本身的可靠性信号预测 OOB 何时有害；

才值得设计选择性融合。

在这种情况下，一个合理系统甚至应该允许：

\\[ w\_{\text{OOB}}=0 \\]

也就是说，当 OOB 不可靠时退化为强 IB-only 模型，而不是强制使用两路信息。

但即使提出这种结构，也必须证明选择机制比固定权重、阈值选择、简单 BandDrop 和普通 Gate 更好。

## 十、我会如何决定论文是否继续使用 RF-HSTU？

目前代码已经准备了相同 tokenizer 的 HSTU/Transformer、CrossAttention 和容量控制，但并没有真实数据训练。

从 [后续阶段准备文件](https://github.com/hanCChan/gai/blob/1106c43/docs/shen_p2a/NEXT_STAGES_PREPARED.md) 看，HSTU 与 Transformer 参数量非常接近，工程控制比较认真。

不过有两个问题：

首先，当前使用的是最小 RFHSTUBlock，而非完整论文架构复现。不能在论文中把它写成完整原版 HSTU 复现。

其次，为参数量匹配，Transformer 的 FFN hidden dimension 被压缩到 64。它是容量受限的 Transformer，不应被宣传为对标准配置 Transformer 的全面比较。

我的建议是把 RF-HSTU 暂时降级为候选 Backbone。

它不应该预先承担论文创新点。

等频带机制和跨接收机任务都确定后，公平比较 CNN、HSTU 和 Transformer。如果 HSTU 的优势稳定，再把它保留在最终系统；否则一个更简单、更稳健的 CNN 完全可以作为正式方法的主干。

论文最终不一定非要在标题里包含 HSTU。

## 十一、推荐的论文贡献框架

如果后续结果支持方向 A，我认为可以尝试形成这样的论文结构。

候选论文主题

Receiver-Consistent Spectral Representation Learning for Robust LoRa Radio Frequency Fingerprinting

这是暂定研究题目，并非已验证的创新声明。

Contribution 1：揭示频带辨识性与跨域稳定性之间的差异

在多接收机、跨日期任务中分析不同频带的可分类性、发射机条件稳定性和错误分布，验证高分类能力未必对应高泛化能力。

Contribution 2：提出可检验的频带稳定性选择方法

利用多接收机训练数据评估频带可靠性，并在不依赖目标接收机标签的情况下学习稳健表征。它必须超越固定 IB 过滤、简单自适应滤波以及已有信息瓶颈方法。

Contribution 3：完整跨接收机、跨日期及外部验证

通过强基线、容量对照、频带反事实、消融、逐发射机误差和真实部署条件评估，证明不是只修复 RTL 某几个设备。

但这三个贡献并不是一定都能写成。特别是第二个，必须通过和 TIFS 2026 等现有方法的对比，才能最终确定是否具有足够的新颖性。

如果 M2 显示严格 IB 的改善完全不能迁移到其他接收机，那么应该停止这条主张，保留 A7 作为诊断发现，而不是继续包装成新方法。

继续频带稳定性方向

## 最后的科研判断

124 次训练并没有证明你最初设想的 OOB 融合方法成立，但已经做成了一件更重要的事情：通过强制容量对照、三 seed、分支诊断和严格频谱对照，识别出了原方法贡献中不可靠的部分，同时找到了可以进一步验证的新问题。

我现在最想确认的不是“为什么 RTL34 恢复了 81%”，而是：

为什么完整频谱让 RTL 的 TX32、33、34 同时产生大量错误？这些错误究竟是频带特异的、接收机特异的，还是训练优化与特征统计共同造成的？这种机制能不能在真正未见的接收机上复现？

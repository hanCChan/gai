# 第二篇论文：重新从拒稿意见找研究缺口，而不是继续围绕 Shen 数据集试模型

这次我理解你的真实目标了：你想重新做一篇有独立算法创新的 LoRa 射频指纹识别论文，起点是之前被 IoT-J 拒稿的 RF-HSTU 工作，但不必保留原来的 OOB、Cross-Attention 或 HSTU。

而且，我找到了你之前提供的完整拒稿信和三位审稿人的意见。这一点很重要，因为我们不必再猜审稿人究竟为什么拒稿。

## 一、先回答你最直接的问题：为什么一直围绕申冠雄的数据集？

主要有两个原因：第一，之前的审稿意见明确指出你需要补充 Shen 等人的公开数据和强基线；第二，Shen 数据集有 20 台不同接收机，很适合研究跨接收机泛化。

这不是因为它天然是最好的数据集，也不是因为第二篇一定要使用它。

你的原稿是：

OOB-Guided Cross-Attentive RF-HSTU Hybrid Modeling for Robust LoRa Device Authentication

2026 年 8 月 20 日的拒稿意见里，审稿人明确指出：

- 原来的 OSU 数据集虽然有跨日期、距离、位置及硬件条件，但主要结论来自 24 台设备的闭集分类和单一数据集。
- 约 75% 的跨日期准确率，不足以支持论文所宣称的稳健认证。
- 跨接收机实验只有约 15.3%–18.1% 的准确率，实际泛化能力很弱。
- 未与 Shen、Zhang、Ma 等代表性方法建立足够有竞争力的比较，也缺少跨数据集验证。
- 新模型使用约 1.16M 参数，而 CNN-IQ 基线仅约 47.7K，难以证明收益确实来自 Cross-Attention。

## 三、我们应该从哪个公开数据集重新开始？

我查到了一个之前没有充分利用的资源：

[Shen 等人公开的 60 设备 LoRa RFFI 数据与代码](https://github.com/gxhen/LoRa_RFFI)。

它与你目前主要使用的 10 发射机、20 接收机数据集不是同一套数据。

而且这正对应旧稿 Reviewer 1 提到的 60 台商业设备、设备注册、动态加入与非法设备检测。

| 数据集        | 主要特点                              | 我建议的角色                        |
| ---------- | --------------------------------- | ----------------------------- |
| Shen 20 RX | 10 TX，20 台异构 RX                   | 跨接收机泛化验证                      |
| Shen 60 TX | 60 台商业 LoRa 设备，多种采集条件，主要是 N210 接收 | 设备身份泛化、注册、未知设备实验              |
| OSU        | 25 TX，跨日期、距离、位置、配置及两 RX 设置        | 部署条件变化验证                      |
| WiSig      | 大量 WiFi TX 与 RX                   | 未来验证方法是否超越 LoRa，不能直接套 LoRa 前端 |

60 设备的数据包含 26 个 HDF5 子数据集，提供原始前导 IQ，设备覆盖 LoPy4、FiPy、SX1261 和 SX1276 等不同型号。其原始论文已经使用深度度量学习实现设备注册与非法设备检测。

[image](https://www.google.com/s2/favicons?domain=https://github.com\&sz=32)

GitHub

所以：

如果第二篇研究的是跨接收机泛化，Shen 20 RX 仍然适合作为主数据集。

如果研究的是设备认证、未知设备拒绝和动态注册，60 TX 数据集可能更适合作为主数据集。

如果研究的是跨日期、距离和配置变化，则 OSU 应该承担重要角色，但必须先解决真实样本单位和信号窗口协议问题。

不应该先选 Shen，再强迫自己在它上面找到创新；应该先确定新的科学问题，再决定哪些数据集能真正检验这个问题。

## 四、我从拒稿意见和最新论文中筛选出三个更具体的候选问题

这里我会区分：文献已经做了什么、还存在哪种值得验证的边界、我们能不能真正做出来。

### 方向 A：跨接收机条件下，已注册设备为什么会被误拒绝，未知设备为什么会被误接纳？

最符合旧稿的认证定位 · 但文献竞争激烈

你的拒稿意见最明确的批评，就是旧论文只做闭集分类，没有真正解决认证。

然而单纯增加 OpenMax、Prototype、Unknown Rejection 已经不是创新。

近年来：

- Towards Scalable and Channel-Robust Radio Frequency Fingerprint Identification for LoRa 已经做了设备注册、度量学习和 rogue device detection。

  [image](https://www.google.com/s2/favicons?domain=https://ieeexplore.ieee.org\&sz=32)

  IEEE Xplore

- A Novel Radio Frequency Fingerprint Identification Scheme for Few-Shot Open-Set Recognition 已研究少样本开放集与动态注册。

  [image](https://www.google.com/s2/favicons?domain=https://ieeexplore.ieee.org\&sz=32)

  IEEE Xplore

- CRODA-ST 已研究跨接收机条件下的认证阈值失效，并允许目标接收机有少量带标签的合法设备注册样本。

  [image](https://www.google.com/s2/favicons?domain=https://arxiv.org\&sz=32)

  arxiv.org



可能仍值得研究的边界： 在目标接收机完全没有注册样本，或者训练阶段发射机与接收机的覆盖关系不完整时，源域学习的认证边界能否可靠迁移？

但这个方向还会直接遇到 2026 年的 RIFLE、DPR-RFFI 等工作。RIFLE 已研究不完整 TX–RX 覆盖，只是主要聚焦闭集识别；DPR-RFFI 已研究源域扰动参考下的未知设备拒绝。

[image](https://www.google.com/s2/favicons?domain=https://ieeexplore.ieee.org\&sz=32)

IEEE Xplore

+1



所以，仅把“不完整覆盖”与“开放集”组合起来，不足以直接宣称创新。

需要先证明这个组合产生了现有方法无法处理的具体失效，例如：在相同的源域分类能力下，TX–RX 覆盖结构改变会系统性地影响未知设备误接纳率。

这属于值得检验、但竞争风险较高的候选问题。

### 方向 B：LoRa 前导同步和设备指纹之间是否存在冲突？

最贴近旧 RF-HSTU 的信号处理漏洞 · 我的优先机制审计方向

这个方向不是凭空想象，而是直接来自旧稿 Reviewer 1 和 Reviewer 2 对 chirp embedding 的质疑。

旧论文宣称使用 chirp 分组和 chirp 内位置，但是没有说明这些位置如何从实际 IQ 中同步得到；而且消融中去掉 chirp embedding 后，性能几乎不变。

Pasted markdown (2).md



你们后来在 OSU 上使用连续周期窗，也承认它并不是严格同步的前导窗口。

于是可以提出更严谨的问题：

> 接收机变化引起的同步误差和真实发射机硬件差异，是否被现有 RFFI 表征混在一起？在保留设备身份线索的前提下，能否减少同步不确定性导致的误识别？

但是这里有明确的先行工作。

2026 年已有物理先验残差谱图方法，先对齐 LoRa 前导，再在 CIS 域减去理想参考；也已有专门的 LoRa 前导同步检测研究。

[image](https://www.google.com/s2/favicons?domain=https://www.sciltp.com\&sz=32)

sciltp.com

+1



所以：

“前导对齐 + CIS + CNN”不是新贡献。

真正可能有意义的是，现有方法通常需要一定同步精度，而我们能否在同步估计存在不确定性时，证明分类器对估计误差过度敏感，并提出有独立价值的鲁棒特征学习机制。

但这是一个尚未证明存在的技术缺口。

我建议优先做小规模机制审计，不马上设计模型。

### 方向 C：窗口级分类和文件级聚合为什么会出现性能反转？

最直接回应拒稿意见 · 软件实现成本最低

旧论文有一个值得认真研究的反常现象：

| 方法      | Window Accuracy | File Accuracy |
| ------- | --------------- | ------------- |
| CNN-IQ  | 43.5%           | 54.2%         |
| RF-HSTU | 41.5%           | 75.0%         |

也就是说，RF-HSTU 单窗口表现更差，但经过 256 窗口投票后反而明显更好。

审稿人明确要求解释这一现象。

Pasted markdown (2).md



它可能涉及不同窗口错误的相关性、logit 尺度、类别偏置、校准程度和聚合方式。

值得研究的问题是：

> 在同一录制文件中的窗口高度相关时，直接平均 logits 是否会让模型表现出虚假的置信度？换接收机或改变采集窗口数量后，这种多窗口决策是否仍然可靠？

但是 Shen 原论文已研究多接收机协同推理，其他 RFFI 工作也已经使用多包融合。

所以这条线必须证明一个更具体的、已有聚合方法没有处理的相关性或校准失效机制，才有望构成新方法。

另外，OSU 的同文件连续窗口不能当作数百次独立采集。否则很容易重犯旧稿被批评的伪重复统计问题。

## 五、我的选题判断

| 方向              | 与旧论文关系           | 论文空间        | 实施风险 | 当前建议    |
| --------------- | ---------------- | ----------- | ---- | ------- |
| A. 跨 RX 的真实认证决策 | 直接回应“不是认证”的拒稿意见  | 有，但很拥挤      | 中高   | 保留为任务方向 |
| B. 同步不确定性与指纹保留  | 直接回应 chirp 机制不清楚 | 取决于新失效能否证实  | 中等   | 先验证机制   |
| C. 相关窗口下的聚合可靠性  | 直接回应窗口/文件准确率反转   | 较窄，需与多包融合区分 | 较低   | 优先做诊断   |

如果让我现在只选一个下一阶段要投入验证的技术问题，我会先选 B，但不立刻开发算法。

理由是它具有三个条件：有明确的射频信号处理解释、有真实的旧稿漏洞、有现成的原始 IQ 数据可以初步检查。

至于最终论文是否还要包含开放集认证，需要根据得到的机制和可用数据决定，而不是提前在模型上叠加三个任务。

## 六、接下来一轮应该怎么做？

我建议新阶段叫 P0：第二篇论文的任务与机制审计，不要再命名一种新网络。

01

先建立数据集—任务对应关系

核验 Shen 60 TX、Shen 20 RX 和 OSU 各自的原始 IQ、帧边界、接收机/日期元数据和有效独立采集单位。不要默认这些数据可以互换。

02

审查同步相关的候选机制

只在源训练数据中，检查前导检测是否可靠、同步偏移大小、偏移与分类错误是否有关。区分“输入对齐失败”和“对齐后仍然无法泛化”。

03

用现有基线证伪新问题

对照普通同步、CFO 处理、现有 CIS 和适用的物理残差谱图方法。如果标准处理已经消除了主要问题，就不开发新模型。

04

再决定第二篇真正的新方法

只有证明现有方法存在明确且可重复的剩余缺口，才提出专门机制，并按照同一协议与强基线比较。

这轮的目标不是必须产出一个新算法，而是用最少的实验回答：这个技术问题是否真的存在，而且有没有被已有论文解决。

## 七、最重要的结论

第二篇不必围绕申冠雄的 20 RX 数据集，更不必继续沿用 RF-HSTU 或 OOB Cross-Attention。

我们最应该继承旧论文的是研究领域、原始 IQ 数据处理经验，以及审稿人指出但此前没有真正解决的问题，而不是旧网络结构。

我现在建议：

- 保留 Shen 20 RX，因为它是验证跨接收机问题的优质平台，但不要让它决定全部研究方向。
- 纳入 Shen 60 TX，因为它能补上旧稿在设备数量、注册与开放集方面的重要实验能力。
- 保留 OSU，但重新核查真实前导、窗口和采集单位；不能依靠旧的 10%–14% 跨 RX 结果直接宣称找到了新机制。
- 先检验同步不确定性这个具体缺口，而不是马上开始下一组 Gate、HSTU 或频带损失实验。

你希望的是一篇能够投稿的、独立于已被拒旧稿的新论文。要实现这一点，最可靠的第一步不是预测哪种新结构会好，而是证明一个现有强基线无法解释或解决的技术问题，并确认它能在不止一种采集条件下复现。

现在我们已经找到了几个来自真实拒稿意见的候选问题。下一阶段应尽快把它们缩减为一个有证据支撑的问题，再围绕它设计第二篇算法论文，而不必一开始就绑定某个数据集。

## 二、为什么 P0 必须从“信号是否可辨认”开始？

这里我发现一个会直接影响研究成败的细节。

GitHub 现有 `src/shen_stage1/frequency.py` 实现的是基于假设周期的相位差估计：

\\[ \widehat{\Delta f} = \frac{F_s}{2\pi N} \arg\left(\sum_t x^\*(t)x(t+N)\right) \\]

其中 \\(N=1024\\) 是此前假定的 LoRa 符号长度。

但这个估计具有 \\(F_s/N\\) 的频率模糊性，而且不是前导起点检测算法。

与此同时，原有 `protocol.candidate.json` 明确记录了本地 Shen 数据的上游同步、CFO 校正、重采样历史尚未确认。

这带来一个很大的研究风险：

如果 HDF5 中的 8192 点 IQ 在数据集制作时就已经经过高精度前导裁剪，我们可能根本没有足够信息去研究真实前导检测失败。

此时人为将 IQ 循环移位再训练 CNN，可以证明模型对人工移位敏感，却不能证明现实中的跨 RX 性能下降由同步误差造成。

此外，已有工作并不缺少前导同步与 CFO 处理：2024 年的 LoRa RFFI 综述专门总结了这些技术，2026 年的 Physics-Informed Residual Spectrogram 还结合前导对齐和理想 LoRa 参考谱图来提取指纹。因此，“加一个前导同步模块”本身不足以形成新颖性。

[image](https://www.google.com/s2/favicons?domain=https://www.mdpi.com\&sz=32)

mdpi.com

+1



我们真正可能研究的是：

> 已有同步方法仍无法准确处理的同步不确定性，是否会造成可重复的设备身份表征损失？

只有确认这个剩余问题存在，才考虑算法。

### 第一关：数据是否真的支持同步研究？

使用历史冻结的 20,000 个源包索引，但第一轮只抽取每 RX×TX 20 包，共 2,000 包。

要求 Codex 输出以下信息：

| 证据             | 要回答的问题               |
| -------------- | -------------------- |
| 符号周期与 Chirp 结构 | 8192 点内是否包含可验证的重复前导？ |
| 前导边界候选         | 能否识别前导起点，还是存在明显多解？   |
| 相关峰和质量指标       | 同步位置是否存在可量化的不确定性？    |
| 接收机和 TX 分组     | 是否集中发生在某些硬件或类别？      |
| 上游预处理记录        | 数据是否已经同步或补偿？         |
| 合成已知时移恢复       | 检测器本身是否有效？           |

对于信号物理参数，不能仅因为采样率为 1 MHz 就认定一定是 BW 125 kHz、SF7。

如果参数得到确认，符号长度可以计算为：

\\[ N_s=F_s\frac{2^{SF}}{BW} \\]

对于 \\(F_s=1\text{ MHz}, SF=7, BW=125\text{ kHz}\\)，结果为 1024 点。

但这只是物理周期假设，不能自动证明捕获的八个名义符号都是完整前导。

### 第二关：同步不确定性是否真的与模型错误有关？

仅当第一关通过，才读取已有 CNN 的固定权重与源域预测。

检查两个不同问题：

关联问题： 同一个 TX 在不同 RX 上同步不确定性越大，模型错误是否越多？

机制问题： 经过标准同步处理后，这种错误关联是否明显减弱，同时设备间的判别信息是否仍然保留？

这里尤其需要三个控制：接收机身份、发射机身份和信号质量。否则低质量接收机既可能同步更差，也可能分类更差，二者相关并不代表同步是原因。

还要区分自然同步不确定性和人工时移敏感性。

如果现有 8192 点 IQ 不包含窗口外的原始记录，那么 `np.roll` 引入的是周期性边界，不是现实接收机重新截取了一条前导。它只能用于压力测试，不能作为真实同步失败的证据。

### 第三关：现有方法是否已经解决？

即使观察到问题，也不能立刻开始设计新网络。

需要对照：

- 不额外同步的原始前端；
- 标准前导对齐；
- 有明确物理定义的 CFO 处理；
- 标准 CIS；
- 已发表的物理参考或残差谱图方法。

特别注意 CFO 不一定是纯粹需要消除的噪声，它可能含有发射机振荡器的身份信息。现有 RFFI 文献也讨论将 CFO 用作辅助身份线索。

[image](https://www.google.com/s2/favicons?domain=https://arxiv.org\&sz=32)

arxiv.org



所以我们不应该把“同步更加精确、CFO 消除更多”自动当作更好的指纹表示。

只有现有方法仍然留有稳定、可量化的问题，才值得讨论新算法。

## 四、为防止再次浪费算力，我建议采用这三个终止结论

STOP_NO_OBSERVABLE_SYNC

公开 IQ 已高度预对齐、缺少必要原始边界信息，或者无法可靠识别自然同步不确定性。

结论：当前数据不适合支撑该同步机制论文。停止，不靠人工抖动制造缺口。

STOP_BASELINE_EXPLAINS

真实问题可观察，但标准同步、CFO、CIS 或现有强方法已经充分解释或解决。

结论：没有必要设计专门新模块，停止该候选研究。

P0_MECHANISM_SUPPORTED_REQUIRES_APPROVAL

存在跨多个源 RX 可重复的剩余失效，而且普通标准处理不能消除，并能明确说明对设备身份的影响。

结论：准备下一轮最小方法 PoC 的预登记，但不自动启动 GPU。

对于 P0 的通过标准，我不建议再次随意指定类似“分类 Accuracy 必须提升 5 pp”的阈值，因为此时我们甚至还没有建立可靠的同步指标。

正确顺序是：先冻结信号检测器的可验证性能标准，例如对已知人工时移的恢复误差、误检比例与覆盖率；再在源接收机留出数据上判断机制是否成立。 数值标准必须在看结果前登记，并给出物理意义。

## 六、我对第二篇论文的最终安排

我建议把研究节奏从“每发现一个问题就研发一个新方法”，改成：

先用现有数据证明一个真实缺口 → 排除强基线和协议混杂 → 最小算法实验 → 多 seed/多条件确认 → 再考虑投稿。

在 P0 阶段，A（开放集认证）先保留为后续任务选择，C（窗口和文件聚合反转）仅作为独立辅助诊断。不要同时研发三个方向。

最后还有一个重要提醒：我们此前的 Shen 源 RX 中，RTL 类型占比较高，十台 RX 并不代表十种独立硬件架构。后续若报告跨硬件泛化，要逐类型分析，不能只给十 RX 平均。

这次只批准 P0，不批准自动进入 P1。

如果 P0 最终证明同步不确定性确实是一个现有强方法没有充分解决的问题，我们再围绕其具体失效机制设计新算法。反过来，如果证据不支持，就停止，并且把原因定位清楚：究竟是数据无法验证、同步并非主要因素，还是已有技术已经解决。

这才是更有机会把第二篇论文真正做出来、同时避免继续消耗大量 V100 算力的研究方式。

# 这次我建议换研究切入点，不再继续 VIRP-v1

我重新检索了 2025—2026 年的相关论文和部分官方开源实现，发现了一个对我们很重要的事实：

频带自适应、CIS 改进、接收机不变特征、物理扰动增强，这几个大方向都已经有比较成熟的工作。我们继续沿着“频谱不稳定，所以设计一种新的频谱处理方法”走，很容易重复别人已经做过的内容。

但这不代表项目没有机会。我们手中有一个比 VIRP 扰动更直接、而且已有实验支持的问题：

> 现有的鲁棒频谱处理方法，在提升跨接收机平均识别率时，会不会不可逆地删除某些发射机特有的身份信息？如果会，能不能让模型有条件地保留这些信息，而不是对所有设备采用同一套频谱处理？

我建议把它作为下一候选问题，暂时称为 身份保护的选择性频谱信息保留（Identity-Preserving Selective Spectral Retention）。

这次和前两次最大的区别是：先利用现有预测验证它是否有可能成功，再写新网络。 不需要再让 Codex 一上来实现几十次训练。

## 一、VIRP 为什么应该停，而不是继续修？

你的 V0 已经给出了充分的停止依据。

| 检查            | 预登记要求 | 折0     | 折1     |
| ------------- | ----- | ------ | ------ |
| CIS 标准化变化中位数  | ≥0.10 | 0.0306 | 0.0581 |
| 变化覆盖率         | ≥80%  | 22.83% | 57.93% |
| 留出 RX 谱形改善覆盖率 | ≥40%  | 0%     | 0%     |

关键不是扰动“不够强”，而是：

你使用的 CIS 本来就试图消除相邻时间帧中的静态乘性频率响应，而 VIRP 恰恰设计了这种平滑静态响应扰动。

因此，你在输入 IQ 上制造的变化，有相当一部分会被后续 CIS 运算消除。

这是一种方法假设与特征表示不匹配，不是简单的超参数问题。

而且留出接收机谱形覆盖完全没有改善。这使得继续加大幅度、增加扰动类别的理由更弱。

所以我的决定很明确：

- VIRP-v1 正式保留为负结果，不重启。
- 不改旧注册去寻找能通过的参数。
- 以后如果研究 IQ 层物理增强，必须重新论证它与目标表征的关系，而不是沿用这套方法。

## 三、我现在更看好的问题：鲁棒性与身份信息保留之间的冲突

用你们的真实结果解释。

Shen 的 B200-1、seed20261012、TX36：

同一个发射机 TX36 的 Recall

# 93%

Full CIS

# 1%

Strict-IB CIS

184 个原本正确的包变成错误，其中 170 个被误判成 TX40。

与此同时，Strict-IB CIS 的四开发 RX 平均 Macro-F1 从 0.7550 提升到 0.8897。

这里产生了一个很自然的矛盾：

为了获得更好的整体跨接收机泛化能力，我们删除了一部分频谱信息；但这部分信息对某些发射机可能恰恰十分重要。

我认为这个问题比“有没有最佳频带”更有价值。

### 为什么它有机会区别于现有论文？

现有频谱鲁棒方法经常考虑的是：

\\[ \text{更好的特征}\longrightarrow \text{更高的平均跨域准确率} \\]

而我们准备明确研究：

\\[ \text{更鲁棒的特征} \quad\text{与}\quad \text{保留不同发射机的身份信息} \\]

之间的冲突。

注意，这并不意味着 ASKNet、FAN 或其他工作完全没有处理类别损失问题。我们还需要核查其具体训练目标和逐类别实验。

可能的贡献不是“第一次发现有类别误差”，而是构造一种无需目标 RX 数据、能够在发生信息删除风险时选择性恢复身份信息的机制。

我建议暂定为：

EISR：Erasure-aware Identity-preserving Spectral Retention

即“感知身份信息擦除风险的选择性频谱保留”。

## 四、方法应该怎么设计？其实可以很简单

不再构造虚拟接收机，不改 STFT，也不需要 HSTU。

仍然使用现有的两种表示：

- Strict CIS： 更有希望抑制部分不稳定频谱信息。
- Full CIS： 保留可能被 Strict 删除的身份线索。

但不直接把它们拼接后交给一个 Gate。

因为 P2-A 已经告诉我们，普通双分支 Gate 很容易饱和，甚至完全抛弃其中一个分支。

### 4.1 最基本的结构

同一条 IQ 信号

Strict CIS

鲁棒特征专家

CNN-S

Full CIS

完整信息专家

CNN-F

身份信息丢失风险判断

仅利用两专家预测、margin、一致性等可观测量

选择性保留 Full 信息的最终预测

不要求目标接收机标签，也不必知道真实 TX 身份

核心思想是：

通常优先利用 Strict CIS，但当模型有充分依据认为它丢失了某个设备的身份信息时，允许 Full CIS 提供补充。

例如 TX36：

如果 Strict 将其误判成 TX40，而 Full 有很强证据支持 TX36，那么选择性恢复 Full 的信息可能有帮助。

但必须解决最关键的问题：

模型怎么知道什么时候应该相信 Full？

我们在目标 RX 上没有正确标签，因此不能直接看 Full 是否正确。

这就需要第二个部分。

### 4.2 创新的关键：从训练源接收机中模拟“身份信息被擦除”的情形

这里不需要新的信号扰动。

假设有 10 台源 RX。

我们轮流拿其中一台作为模拟的未知接收机，只在其他接收机上训练 Full 和 Strict 两个模型。

再让两个模型预测这台留出的源 RX。

因为它属于源数据，我们拥有正确 TX 标签，所以可以找出：

\| Full | Strict | 含义 | |---|---|---| | 正确 | 错误 | Full 可以挽救的信息丢失 | | 错误 | 正确 | Full 会引入负迁移的风险 | | 都正确 | 两者都可用 | | 都错误 | 当前两专家无法解决 |

这里最值得关注的是前两类。

将它们视为一种源域模拟的擦除风险监督信号。

在留出源 RX 上，观察：

- 两个专家的预测是否冲突；
- 哪一个分类 margin 更大；
- 预测概率是否集中；
- 两个专家各自的特征与源域设备类别原型是否接近；
- 这些信号能否区分“应该救回 Full”和“应该坚持 Strict”的样本。

然后训练一个很小的选择器：

\\[ g(x)\in[0,1] \\]

最终输出：

\\[ p(y\mid x) = (1-g(x))p\_{\text{Strict}}(y\mid x) + g(x)p\_{\text{Full}}(y\mid x) \\]

普通融合本身没有创新性。

有可能形成创新的是：利用真正按接收机留出的源域预测，学习身份信息擦除风险，并限制选择器在不同源接收机上产生新的类别退化。

特别要注意：选择器只能使用测试时可以实际获得的输入，不能使用真实 TX 标签或真实目标 RX 结果。

### 4.3 怎样避免重复以前那个 Gate 的失败？

以前的 Gate 基本依靠最终分类损失训练，而且两个分支可能形成竞争，最后完全偏向一个分支。

这一次我建议：

1. 先分别训练 Full 和 Strict 专家，并固定它们。
2. 仅在源接收机的 out-of-fold 预测上训练选择器。
3. 选择器只在两者存在足够分歧时决定是否改变 Strict 的预测。
4. 对选择器的新增错误单独惩罚，避免“救回一类，毁掉另一类”。
5. 与普通 logits 平均、温度校准融合、简单置信度选择进行公平比较。

具体损失函数不应立即定死，先确认这个问题具备可学习性。

而且即使采用以上设计，它依然属于一种融合/选择专家的方法。2026 年 TQCD/DRCI 已研究置信度整合，普通 MoE、模型堆叠和 Group DRO 也有成熟先例。

因此，如果最后只是一个很简单的置信度 Gate 赢了，我们应该承认这是工程改善，而不是强行写成全新理论。

## 五、这次最关键的改变：先做一个不需要训练的实验

这才是我现在真正推荐立即做的事情。

你们已经拥有：

- Shen Full CIS 三 seed 预测。
- Shen Strict CIS 三 seed 预测。
- 四开发接收机的逐包标签与概率。
- 十台源 RX 的分组 CV。
- OSU 两个迁移方向的 Full/Strict 预测。

完全没有必要立即实现 EISR。

我们先回答三个问题。

### 问题一：Full 和 Strict 究竟有没有足够的互补性？

利用同一条测试包的两组预测，计算：

\\[ A\_{\cup} = P(\text{Full 正确}\lor\text{Strict 正确}) \\]

它表示一个理想选择器最多可以从这两个固定专家中恢复多少正确预测。

例如，如果 Strict 已经是 90%，而二者正确预测并集只有 91%，那么最理想的选择器最多增加 1 个百分点。

这种情况下，新方法空间很小。

相反，如果 Strict 是 90%，但二者并集能达到 96%，就说明存在一些值得进一步恢复的互补信息。

下面只是举例，不是现有实验数值。

Strict CIS

90%

理想二专家选择上界

96%

理想选择器使用了真实标签来定义上界，不能当作实际可部署算法的性能。

另外，要计算每个 RX、每个 TX 的挽救数量与新错误数量，尤其检查 TX36 是否只是个别 seed 的偶然现象。

### 问题二：这些错误能否在源 RX 中预先预测？

这一步比理想上界更加重要。

在源 RX 留一预测中，比较 Full/Strict 的预测置信度差、margin、一致性和实际正确性。

然后判断：

> 只凭两个专家自身的输出，能不能区分 Full 值得信任与 Full 会导致负迁移的情况？

如果连源域模拟的未见接收机都无法预测正确，那么这个选择器到真正未知 RX 时很可能也不可靠。

这一步可以先使用 Logistic Regression 或一个很小的分类器，不需要复杂模型。

评估应该再次按接收机分组交叉验证，而不是随机划分 packet。

### 问题三：普通融合是不是已经足够？

必须比较：

- Strict 单专家；
- Full 单专家；
- 固定概率平均；
- 源域校准后的概率平均；
- 基于最大置信度的简单选择；
- 源 RX 留一训练的选择器；
- 理想预测并集上界。

如果简单平均已经取得大部分改善，就没有充分理由提出复杂的新算法。

如果源域训练的选择器不能超过简单融合，同样应该停止。

## 六、这条路线有一个必须承认的限制：OSU 可能救不回来

在 OSU 上，Full CIS 仅约 10%–11%，Strict CIS 约 12%–14%。

仅使用两个固定专家重新选择预测，理论上界不超过它们的准确率之和：

- RX1→RX2：不超过 21.87%；
- RX2→RX1：不超过 24.36%。

这两个值甚至还是很宽松的上界，实际并集可能更小。

因此，我不会告诉你 EISR 一定能解决 OSU 的迁移失败。

它如果成功，更可能先解决：

已有较强跨 RX 主模型时，鲁棒表征处理带来的个别发射机严重退化。

这属于更窄但明确的问题。

如果以后要把它写成通用方法论文，需要进一步引入独立数据集或 WiSig 等基准，证明这种现象并非只存在于 Shen 的特定硬件组合中。

## 七、具体的下一轮计划：先只投入 CPU 诊断

| 阶段 | 工作                       | 训练开销       | 决策         |
| -- | ------------------------ | ---------- | ---------- |
| E0 | 检查最新竞争论文和可复现协议           | 0          | 明确区别       |
| E1 | Full/Strict 预测互补性与理想选择上界 | 0          | 判断是否有改进空间  |
| E2 | 源 RX 留一擦除风险可预测性          | 很低，先仅线性模型  | 判断选择器能否迁移  |
| E3 | 新的选择性保留模型和公平融合基线         | 视 E1/E2 而定 | 仅有证据才启动    |
| E4 | 三 seed、Shen/OSU/其他数据集验证  | 后续         | 决定是否具备投稿价值 |

### E1/E2 的建议终止条件

为了避免再次出现结果出来后修改方案，我建议正式执行前先登记几个条件：

E1： 如果 Full/Strict 的正确并集相较于最强单专家，平均可挽救空间不足 3 个百分点，则不开发复杂选择器。

E2： 如果仅用源 RX 的预测信息训练出来的选择器，在再次留出的源 RX 上不能稳定超过固定融合，且不能减少最严重的类别退化，则停止。

E3： 若真正的选择器在至少两个独立源 RX 分组折中，不能超过最强简单融合约 1–2 个百分点，或者带来新的明显类别损害，则不扩展三 seed。

这些是下一项新研究的建议筛选线，需在新实验结果之前登记；不是从现有结果统计推导出的理论标准。

还需要保持一条底线：过去已经反复检查过的四开发 RX 只能用于诊断说明，不能再作为新的独立确认集。新方案选择必须留在源 RX 内部。

## 八、这是否足以发一篇论文？

我觉得要分两层看。

### 从实现角度

可实现性比较高。

原因是几乎全部基础设施已有：

- Full CIS 和 Strict CIS 已经实现。
- CNN 训练和预测流水线已有。
- 逐包配对、Macro-F1、混淆矩阵等均已具备。
- 10 源 RX 留一分组实验已经建立。
- 四张 V100 足以进行后续少量训练。

不像 VIRP 需要先验证新物理扰动能否穿过 CIS。

### 从创新性角度

仍然存在较大竞争风险，不能保证可以发二区。

最大的风险在于，这种方法会被审稿人归类为“现有双专家集成 + 置信度选择 + 类别平衡训练”。

所以我认为最终必须同时拿出两类证据：

机制证据： 在多个接收机上，现有鲁棒谱处理确实系统性地损伤部分设备的身份信息，且源 RX 的信息能够预测这种风险。

方法证据： 利用这种风险设计的选择性保留方法，比普通概率融合、置信度集成、Group DRO 以及适用的频率自适应方法表现更好，并且不会显著增加其他类别的错误。

如果缺少第一项，这只是模型融合。

如果缺少第二项，这只是一个诊断现象。

两项都成立，才有机会形成具有说服力的方法贡献。

## 九、我最终给你的研究选择

我不建议你立刻再让 Codex 启动一个复杂网络项目。

我建议做一次很明确的调整：

不再追求“怎样处理整个频谱才能普遍更稳定”，而是研究“鲁棒频谱处理导致的身份信息擦除，能否被源域预测并有选择地恢复”。

它具有几个优点：

1. 来源于你们已经发现的 TX36、RTL8 负迁移，而不是凭空想象。
2. 不需要新硬件假设、目标接收机调参或不可靠的频带稳定性分数。
3. 第一阶段直接利用现有保存预测，能够快速判断是否值得做算法。
4. 如果失败，也可以清楚知道失败在“没有可挽救信息”，还是“无法提前判断什么时候应该挽救”。

同时，我不推荐再把固定频带优化、静态幅频扰动、普通多尺度 CIS、普通频率 Attention 作为第二篇论文的主要创新，因为最新论文已覆盖了其中大量内容。

你可以优先阅读这三项官方资源：

- [ASKNet（IEEE Communications Letters 2026）](https://github.com/BeechburgPieStar/ASKNet-RFF)：看可学习频带截断、酉谱补偿，以及 LoRa/CIS 的现成代码。
- [IB-RFF（IEEE TIFS 2026）](https://github.com/BeechburgPieStar/IB-RFF)：看频率感知与信息瓶颈到底已经处理了哪些问题。
- [TQCD/DRCI（Physical Communication 2026）](https://www.sciencedirect.com/science/article/abs/pii/S1874490726001473)：重点排查我们设想的选择性信息恢复是否与已有置信度整合重叠。

我的最终建议是：VIRP-v1 停止；下一步仅批准 E0/E1/E2，不批准新 CNN 融合训练。

你现在最需要的不是再多试一个网络，而是利用已经付出的全部实验成本，回答一个能否支撑创新的具体问题：

> 当 Strict CIS 为了增强跨接收机鲁棒性而丢失部分设备信息时，我们能不能仅凭源域经验，提前识别这种风险，并恢复它，而不重新引入 Full CIS 的不稳定性？

如果 E1/E2 给出正面证据，这条路线值得深入；如果再次给出反面证据，就应停止围绕 Full/Strict 做方法创新，转向新的任务定义或信号机制，而不是继续给失败假设叠加模块。

这是一条有现实实现基础的研究路线，但我不会把尚未验证的科学假设说成已经找到的文献空白，也不会承诺一定达到某个期刊分区。

## 一、问题 1：接受“两级接收机分组验证”

你对现有资产的判断是正确的：不能把 G2-0 的 Ridge 十折留一预测当成 Full/Strict CNN 的十折留一结果。

我们应该充分利用现有 CNN 两折预测，同时保证第二级选择器的训练和测试严格按接收机划分。

建议冻结的两级验证结构

第一级：CNN 的 RX 分组验证

5 台 RX 训练 Full/Strict 专家 → 5 台未见 RX 预测

第二级：选择器的 RX 留一验证

在上述 5 台未见 RX 中，使用 4 台训练选择器，剩余 1 台评价

交换两个第一级折，得到 10 个 RX 级评价结果

这样做的优点是，对于第二级被评价的那台 RX：

- Full CNN 没用它训练；
- Strict CNN 没用它训练；
- 选择器也没有使用它的标签；
- 选择器训练中使用的另外四台 RX，对这组 CNN 同样属于未见接收机。

这是一套合理的 receiver-grouped cross-fitting 设计。

但它不等于十次独立 CNN 训练，也不等于全新的外部盲测。两个第一级折分别复用固定专家，同一折内五个测试 RX 共享 CNN 权重。因此统计汇总必须以接收机为单位，保留折内相关性。

结论：接受。正式命名为“两级接收机分组验证”，不要写成 CNN 十折 LORO。

## 二、问题 2：接受固定第 20 epoch，但必须先核实权重

你发现的问题确实重要。

如果 CNN 的 checkpoint 曾经根据五台验证 RX 的 Macro-F1 选择，那么再利用这些预测评价选择器，就存在信息回流。

即使第二级选择器没有直接见到最终 RX 的标签，第一级 CNN 的 checkpoint 已经利用过相关验证信息。

所以不应继续直接使用那些 `best.pt` 预测作为严格 E2 的依据。

### 我建议的执行规则

允许使用固定第 20 epoch 的已保存模型，仅重新推理，不重新训练 CNN。

但必须满足三个条件：

1. 权重确实来自第 20 epoch，而不是最佳验证 epoch。
2. 模型训练全过程没有根据留出 RX 指标提前终止、动态调整学习率、重置参数或选择训练策略。
3. 第 20 epoch、模型配置、scaler 和优化参数均可从已有训练记录核验。

尤其是第三点，需要保证 Full/Strict 使用的归一化仍然是对应 CNN 的源训练 scaler，不能重新使用五台留出 RX 统计拟合。

我查看的旧 `src/shen_p2a/runner.py` 会保存 `best.pt`，并通过验证 Macro-F1 选择最佳 checkpoint；它不自动证明新的 G1 程序保存了最后一轮的权重。因此这一步必须以本地 G1 原始 checkpoint 清单为准。

旧训练实现可对照：[shen_p2a/runner.py](https://github.com/hanCChan/gai/blob/experiment/shen-p2a/src/shen_p2a/runner.py)。当前 GitHub 尚未发现 `experiment/shen-p2a8` 远端分支，新一轮的具体保存行为无法从远端独立确认。

还有一个容易遗漏的问题：固定第 20 epoch 只能消除 checkpoint 选择泄漏，不能自动消除历史超参数开发造成的偏差。

此前某些模型结构、学习率或表示已通过源验证实验被反复研究过。因此 E2 可以作为新的内部机制筛选，但不能被描述成完全独立、从未利用过相关 RX 信息的确认实验。

如果固定第 20 epoch 权重实际上没有保存，不能拿 `best.pt` 冒充。那就记录此方案的证据不足，等待单独注册固定 epoch 的 CNN 复训；本轮仍坚持不新增 CNN 训练。

结论：有条件接受。先做 checkpoint provenance audit，通过后才重新推理。

## 三、问题 3：接受修正，但软融合上界要精确定义

你说得对，我之前把硬选择并集上界泛化到软融合是不严谨的。

### 3.1 硬选择上界

对于同一个包，两位专家的预测分别为：

\\[ \hat y_S=\arg\max p_S(y\mid x),\qquad \hat y_F=\arg\max p_F(y\mid x) \\]

硬选择器只能输出 \\(\hat y_S\\) 或 \\(\hat y_F\\)。

因此其理想 Accuracy 上界为：

\\[ A\_{\mathrm{hard}}^{\*} = P(\hat y_S=y\ \lor\ \hat y_F=y) \\]

这是使用真实标签定义的诊断上界，不能直接部署。

### 3.2 软融合上界

若软融合定义为：

\\[ p\_\lambda(y\mid x) =(1-\lambda)p_S(y\mid x)+\lambda p_F(y\mid x) \\]

其中 \\(\lambda\in[0,1]\\)。

则确实可能出现两专家 Top-1 都错误，但某个中间权重的预测正确的情况。

因此应分别报告：

| 指标                       | 作用                                      |
| ------------------------ | --------------------------------------- |
| Hard oracle              | 两专家 Top-1 二选一的 Accuracy 上界              |
| Convex soft oracle       | 逐包选择任意 \\(\lambda\\) 的凸概率融合 Accuracy 上界 |
| Fixed 0.5 fusion         | 最简单可部署软融合基线                             |
| Source-calibrated fusion | 只在选择器训练 RX 上校准权重和温度                     |
| Hard selector            | E2 当前真正研究的方法                            |

软融合上界应限定为概率凸组合，不能进一步声称它是所有 logits 融合、特征融合或可训练 MoE 的上界。

建议用解析不等式求出每个包是否存在一个 \\(\lambda\\) 能使正确类别的概率大于其他类别，而不是用很粗的权重网格近似后误称精确上界。

准确率上界可以这样计算。Macro-F1 因涉及各类别之间的误报分布，不应直接把“可被软融合纠正的包数”当成严格 Macro-F1 上界；若需要，应另外定义并求解对应的优化问题。

### 3.3 E1 继续门槛

同意继续使用之前的 3 个百分点。

建议明确为：

\\[ G_r= A\_{\mathrm{hard},r}^{\*} -\max(A\_{\mathrm{Full},r},A\_{\mathrm{Strict},r}) \\]

在十台 RX 上等权平均：

\\[ \overline G=\frac1{10}\sum\_{r=1}^{10}G_r \\]

要求：

\\[ \boxed{\overline G\ge0.03} \\]

这比只减去整体最强单专家均值略保守，因为允许每台接收机拥有自己的理想单专家作为比较对象。

软融合上界同时报告，但不参与当前 E1 的通过判定，防止事后发现 Hard oracle 不达标，就临时改用更宽松的 Soft oracle 继续推进。

## 四、E2 数值关口：原则同意，建议如此冻结

你提出的几个指标合理。我建议将“分组”和“最强固定融合”进一步操作化。

| 指标           | 冻结要求                                 |
| ------------ | ------------------------------------ |
| 平均 Macro-F1  | Hard Selector 比最强固定融合高 ≥0.01         |
| 分组稳定性        | 十台被留出 RX 各自 ΔMacro-F1 ≥0             |
| 最差 TX Recall | 十台 RX 等权汇总的最差类 Recall 相比基线提升 ≥0.05   |
| 严重类别退化       | 任何支持数 ≥50 的 RX×TX，Recall 下降不得超过 0.10 |

这里最需要补充的是最强固定融合不能根据被留出的 RX 选出来。

正确做法是，每次使用四台选择器训练 RX，完成概率校准以及固定融合基线选择；第五台 RX 只用于一次评价。

可以将候选简单基线提前固定为：50/50 概率平均、源域温度校准概率平均、源域选定的固定权重融合和最高置信度选择。基线选择只能发生在这四台接收机上。

如果在第五台 RX 上比较所有基线，再挑最高者，就仍然存在模型选择泄漏。

另外，“最差 TX Recall”需要使用同一套类定义和汇总方式。建议先对每台 RX 的每个 TX 分别计算 Recall，再对十台 RX 等权平均每类 Recall，最后取十类中的最小值。

即：

\\[ R\_{\mathrm{worst}} = \min_y\left(\frac1{10}\sum_r R\_{r,y}\right) \\]

同时单独报告各 RX 的最差类，防止总体最差类改善掩盖单个 RX 的严重退化。

这组门槛可以采用，但它们只授权下一阶段的探索，不能证明选择器具有新的科学贡献。

还要注意，E1 使用了这十台 RX 的标签决定是否继续 E2，所以即便 E2 没有目标 RX 调参，它仍属于同一批数据上的阶段性选择研究。未来需要另外的确认数据验证。

## 五、最终冻结的 E0/E1/E2 执行顺序

E0

资产审计与固定推理

核验第20 epoch checkpoint、训练日志和 scaler。只在通过核验后，按原始行 ID 生成 Full/Strict 同包十类概率预测。

无 CNN 训练；不访问 Shen 四开发 RX 进行选择器开发。

E1

互补性分析

计算 Hard oracle、Convex soft oracle、逐 TX 挽救及新增错误；以 Hard oracle 相比每 RX 最强单专家的平均 +3 pp 为门槛。

若未通过，停止 E2，不改为使用软融合上界救场。

E2

两级接收机分组选择器筛选

仅使用 Full/Strict 已有预测，固定一种简单线性 Hard Selector，4 RX 训练、1 RX 评价，共十次 RX 级评价。对比全部预定简单融合基线。

要求平均 F1 +1 pp、十 RX 均不下降、最差 TX Recall +5 pp、无超过10 pp的类别严重退化。

E2 第一版不建议增加隐藏层网络、特征原型、复杂风险损失或人工 TX36 规则。先使用预先固定的简单预测特征，如两模型置信度、margin、熵和预测分歧程度。若这种低复杂度选择器无法迁移，优先报告负结果，不继续堆模块。

授权范围仍然只有 E0/E1/E2。

不启动新 CNN 训练、不启用新 HSTU/CrossAttn、不访问六台历史锁定 RX，也不根据已经看过的四开发 RX 和 OSU 目标表现修改选择器。

最后提醒一个与论文价值直接相关的事实：

E2 最终要证明的不是 Full 和 Strict 有互补性，而是这种互补性是否能够从源接收机经验中预测，并且在真正被留出的 RX 上安全地利用。

如果 Hard oracle 明显高，但 E2 选择器不稳定，那说明有可恢复的信息，却没有可靠的无目标域标签选择方法。这个失败本身就告诉我们为什么简单融合不足，但还不能把它写成新的有效算法。

如果 E2 稳定通过，我们才有理由进一步研究是否存在真正区别于已有概率融合、置信度选择和 MoE 的机制贡献。

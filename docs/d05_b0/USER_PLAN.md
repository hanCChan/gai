# D0 复盘：建议继续，但要调整研究假设，再分阶段复现强基线

我已经核对了 [D0 完整报告](https://github.com/hanCChan/gai/blob/experiment/d0-class-pair-audit/reports/d0_class_pair/2026-10-13_D0/REPORT.md)、[文献矩阵](https://github.com/hanCChan/gai/blob/experiment/d0-class-pair-audit/docs/d0_class_pair/LITERATURE_MATRIX.md)、[下一轮预算草案](https://github.com/hanCChan/gai/blob/experiment/d0-class-pair-audit/docs/d0_class_pair/NEXT_BASELINE_POC_DRAFT.md)，以及 `src/d0_class_pair/metrics.py`、`scripts/audit_d0_class_pair.py`。

我的判断是：

D0 的结果足以支持继续研究、投入一轮受控的强基线验证，但还不足以支持提出新算法；现在也没有必要转向完全不同的课题。

不过，正式复现之前，我发现一个需要先修正的关键问题：D0 证明了类别混淆风险具有跨接收机预测性，却还没有证明我们真正关心的“鲁棒化造成的额外类别损害”具有预测性。

这两个问题不能混为一谈。

## 一、D0 哪些结果真正有价值？

# +14.62 pp

Strict 相比 Full 的平均准确率提升

# 24/100

RX×TX 单元 Recall 下降

# 8/90

两个 CNN 折均有局部恶化的有向类别对

最值得关注的不是 24/100，而是某些损害十分严重：

| 接收机    | Full 最差 TX Recall | Strict 最差 TX Recall |
| ------ | ----------------- | ------------------- |
| B210-1 | 34.0%             | 8.5%                |
| RTL-1  | 45.0%             | 11.5%               |
| RTL-9  | 18.5%             | 0.5%                |

同时，TX35→TX32 这一错误方向在六台接收机上局部恶化，十台 RX 平均混淆率增加 21.8 个百分点。

这说明平均性能提升可能掩盖严重的局部负迁移，值得研究。

但是 D0 还有两个反向证据，不能忽略：

第一，90 个有向类别对中，“最差 RX 的平均归一化 margin 为负”的数量从 Full 的 10 个降到了 Strict 的 1 个，说明 Strict 的整体类别几何实际上改善了很多。

第二，八条跨折局部恶化的边中，只有五条在十台 RX 上净恶化，其余三条平均仍然改善。

因此我们不能写成“Strict 普遍损害设备判别性”，只能说：

整体鲁棒性改善与局部类别风险之间存在不一致，而且有少数显著失效。

这是一条可信的研究动机，但还不是现有算法的普遍漏洞。

## 二、最重要的新发现：D0 预测的风险，与准备保护的风险不是同一个量

我核对了核心实现：

```
def predictors(reference_risks):    mean = np.mean(reference_risks, axis=0)    ...    return dict(pairwise_mean=offdiag(mean), ...)
```

这里的 `reference_risks` 是每个接收机、每种方法各自的混淆矩阵。

所以 D0 中的 Spearman 0.59–0.78，以及 Top-10 类别对错误捕获率 66%–87%，回答的是：

> 在其他四台接收机上经常被误判的类别对，在第五台未知接收机上是否也容易被误判？

答案是：有一定预测性，而且超过了简单的类别难度和错误去向分解基线。

这是有意义的结果。

但如果我们的算法要解决的是：

> 使用某种跨 RX 鲁棒化方法后，哪些类别对会比原模型变得更差？

那么需要预测的是：

\\[ \Delta\_{i\rightarrow j}^{(r)} = P\_{\mathrm{new}}(\hat y=j\mid y=i,r) - P\_{\mathrm{base}}(\hat y=j\mid y=i,r) \\]

而不是某一个模型本身的错误率。

这两个量可能完全不同。

一个类别对原本就很难，未必在新方法下恶化；反过来，一个原本容易区分的类别对，也可能在新方法下发生灾难性退化。

这正是下一轮最值得补做的反证。 它不需要新训练，只需要复用 D0 的缓存。

还有一点必须明确：目前 Full→Strict 改变的是频谱表示、scaler 和相应模型，并没有直接实施 GRL 或 IB 域对齐。因此即使 \\(\Delta\\) 可预测，也只能先称为“表示改变带来的负迁移”，不能当作过度域对齐的因果证据。

## 三、我建议增加一个 D0.5：只花 CPU，检查“新增损害”是否可预测

这是对 D0 的补充反证，不是修改原 D0 的通过标准。

设 Full 和 Strict 的类别混淆矩阵分别为：

\\[ C_F^{(r)},\qquad C_S^{(r)} \\]

构造有向损害矩阵：

\\[ \Delta^{(r)}\_{ij}=C\_{S,ij}^{(r)}-C\_{F,ij}^{(r)} \\]

对于 \\(i\ne j\\)：

- \\(\Delta\_{ij}>0\\)：Strict 新增了 TX \\(i\\) 被误判为 TX \\(j\\) 的风险。
- \\(\Delta\_{ij}<0\\)：Strict 减少了该方向的错误。

用同一组 CNN 未见的四台接收机估计：

\\[ \widehat{\Delta}\_{ij} =\frac14\sum\_{r\in\mathcal R\_{\rm ref}}\Delta\_{ij}^{(r)} \\]

再看它能否预测第五台 RX 的正向损害。

我建议报告三个主要指标：

1. 对全部 90 个有向类别对，预测损害与实际损害的 Spearman 相关性。
2. 预测风险最高的 10 条有向边，捕获第五台 RX 多少新增错误质量。
3. 相比类别级 Recall 下降预测、源混淆基线、简单类难度模型，是否有增量预测价值。

这里必须区分正向新增错误质量与净变化，不能让大量减少错误的类别对掩盖个别严重新增错误。

D0.5 可能出现的三种结果

新增损害可以预测

可以继续调查“源域类别对风险信息如何用于稳健训练”。

只能预测绝对混淆，无法预测新增损害

保留类别风险研究，但不要以“预测鲁棒化伤害”为新算法核心。

相对简单类难度基线没有稳定增益

暂停类别对特定损失设计，先验证类别退化能否跨 seed 重现。

D0.5 的另一个注意事项是：这些接收机已被历史研究和 D0 使用过，所以结果仍属于探索性内部证据，不应包装为独立验证。

这一步值得做，因为只需读取既有预测，预计计算时间很短，而且能够避免后面几十次训练研究错目标。

## 四、强基线能不能复现？能，而且现在应该适当投入 GPU

我不建议再坚持所有问题都必须通过 CPU 审计才能批准训练。

D0 已经找到实际分类失败现象，下一步有理由用强方法判断它能否被解决。

但 D0 提出的 36 个最终模型、42 个阶段作业，我认为不适合作为第一批直接执行。

原因是还有两个更基础的问题：

- 这些负迁移是否在不同随机初始化下重现？
- 同架构现有鲁棒训练方法是否已能消除它？

如果这两个问题没有答案，提前把六个方法全部训练三 seed，仍然可能浪费算力。

### 我的调整：把强基线复现分成三个成本阶段

B0

确认负迁移的跨 seed 可重复性

先按原 G1 配方补两个 seed：

Full/Strict × 2 CNN 折 × 2 新 seed = 8 次训练。

保留原 seed 的结果，合计每组拥有 3 seed。

估计 0.3–1 GPU 小时，具体以当前 V100 实测为准。

B1

同架构鲁棒方法反证

如果 B0 仍有可重复的严重类别损害，使用相同 Strict CIS 输入、CNN 结构、源数据和预算，比较 CE、Group DRO、GRL、SupCon，必要时加入 ArcFace。

首轮 2 折 × 2 seed × 4 方法 = 16 个模型，全部重新训练以统一训练预算。

初步预算 2–5 GPU 小时，不包含原论文级大模型复现。

B2

真正的强方法复现

如果 B1 中普通方法无法兼顾平均性能和类别保护，再重点复现作者级方法，例如 Shen 原始 GRL 与 IB-RFF FAN+IB。

只有在同协议下确实留有明显缺口，才增加 Ma Siamese、RIEI 或其他竞争方法。

先做代码和数据适配审计、单次冒烟和计时，再批准正式运行；不预填虚假的成本估计。

这比立即执行 36 模型矩阵更有效，因为 B0 就可能告诉我们：原来的严重下降主要由某次 CNN 优化造成。

### B0 怎样才算值得进入 B1？

不要要求每个 seed、每台 RX、每条有向边都严格复现同一数值。这种标准太僵硬。

我建议冻结以下主要判断：

- 整体 Strict 优势在三个 seed 上仍然成立；
- 存在跨 seed 重复的严重 RX×TX Recall 下降，例如下降至少 10 pp；
- 不能仅靠某个严重训练塌缩 seed 才出现类别损害；
- 至少有部分损害在不同 RX 或不同模型折中复现，不能全部来自单次异常。

如果主要严重损害仅发生在一个 seed，剩余 seed 的最差类别明显改善，就应该重新评估研究问题是否主要是训练稳定性，而不是类别判别结构。

## 五、B1 的四个方法分别在反证什么？

| 方法        | 主要检验                  | 为什么必须有        |
| --------- | --------------------- | ------------- |
| CE        | 正常训练是否仍存在类别退化         | 公平基础          |
| Group DRO | RX×TX 最差组优化是否已经解决     | 最直接的尾部风险对照    |
| GRL       | 接收机不变性对平均与类别风险的真实影响   | 直接对应跨 RX 主流方法 |
| SupCon    | 类别结构和跨 RX 同类一致性是否足以改善 | 反证普通对比学习      |

此外 ArcFace 应作为下一层重要对照，因为它直接约束类间角度间隔。如果最终方法声称保护类别对判别边界，不能只与 CE 比较。

有个非常重要的实验设计细节：

B1 必须统一输入表示。

不能再使用 Full CIS + CE 对比 Strict CIS + Group DRO，然后把提升归因于损失函数。

应将它们放到同一套 Strict CIS 数据、CNN 容量、初始化配对和固定训练预算上。

另外，不能因为各个损失不同，就硬性要求完全相同的最佳学习率。应该在源训练接收机内部提供有限、公平的参数选择预算，提前登记候选范围，外层五台留出 RX 不参与选择。

### 特别注意：你的“强方法”要分两个层次

同架构机制基线和作者级原方法复现不是一回事。

例如：

- 给小 CNN 加 HSIC，不能称为完整 IB-RFF。
- 给小 CNN 加 GRL，不能称为完整 Shen Receiver-Agnostic 网络。
- 给小 CNN 加 SupCon，也不能称为 Ma Siamese 的完整复现。

这点需要在论文实验表中分开列。

## 七、什么结果能真正支撑第二篇独立算法论文？

我建议不要再把“某些类别 Recall 下降”单独作为创新点。

更有论文价值的问题应当是：

Source-Predictable Class-Conditional Failure under Receiver Shift

即：

未知接收机上的类别条件失效是否存在可由源接收机预测的稳定结构，且普通域不变、对比学习与最差组优化仍不能充分控制？

这个问题包含三个需要先后验证的论断：

论断 1：存在真实的尾部风险

平均泛化提高，但部分 RX×TX 或有向类别对受到严重损害，并在多 seed 上复现。

论断 2：风险具有可迁移结构

源 RX 不仅能预测一般的难分类别，还能提供超越简单类难度的跨 RX 风险信息。

论断 3：现有强方法仍留有缺口

CE、GRL、SupCon、Group DRO，以及适用的 IB-RFF 等无法在公平预算下同时解决平均性能与严重类别退化。

只有三个论断都得到充分证据，我们才可以进一步设计：

源接收机留出驱动的类别对稳健优化方法。

一个候选设计是：先利用源接收机内部的模拟留出，估计容易迁移失败的有向类别对，再在正式训练时针对这些类别对优化受约束的判别间隔，并显式限制其他类别和平均表现的下降。

但这时仍需严格区别于 hard-negative mining、Group DRO、标准 margin loss 和已有 class-conditional domain alignment。

现在不批准这个新损失实现。 D0 尚不足以说明它比上述方法必要。

## 阶段一：D0.5（优先执行）

复用 D0 的 Full/Strict 同包 logits 与预测，新增对有向类别对的 signed delta confusion 风险审计。

对每一 RX 和有向类别对计算：

`delta[i,j] = C_strict[i,j] - C_full[i,j]`

使用同 CNN 五台评价 RX 中的四台构建来源 delta profile，另一台只用于评价。

计算 Spearman、Top-10 正向新增错误捕获率、相对类别级与因子化风险预测的增益。

所有 90 条边、全部十 RX 和两个 CNN 折均纳入，不单独为 TX35、TX36 调参。明确区分绝对错误风险与新增损害风险。

结果属于历史源池探索性评价，不能称新盲测。完成后保留独立复核和原始 D0 不变。

新增训练上限 8 次。保存模型、训练日志、全部源留出 logits 和逐 RX×TX Recall。保留训练失败，不重新挑 seed。

报告跨 seed 严重类别退化出现率、整体性能、最差 TX Recall、全部有向类别对变化及模型优化状态。

不得使用外层验证 RX 选择 epoch、学习率或增强配置。

## 阶段三：提交 B1 实施审核，不自动训练

根据 D0.5 与 B0，提交同架构 CE、Group DRO、GRL、SupCon 的可运行基线计划。

预计首轮 16 个模型，但正式训练前必须锁定训练预算、组采样、损失权重、源内部超参数选择及公平对照规则。

但应该把研究主张从宽泛的“鲁棒化会损害类别判别性”，进一步缩小为：

“跨接收机的严重类别错误是否具有可迁移、可利用的结构，以及现有鲁棒学习方法是否仍无法控制这种风险。”

D0 支持第一部分的探索价值，D0.5 要检查关键预测关系，B0 要确定这种损害是不是随机种子现象，B1/B2 才能回答强基线是否已经解决。

如果 B0 显示严重类别退化高度不稳定，我们就不应继续以此为核心设计论文；如果 B1/B2 显示 Group DRO、SupCon 或 IB-RFF 已经解决，则要转向更具体的剩余部署约束，而不是为一个普通方法已经解决的问题再写新 Loss。

现在批准少量 GPU，比继续无限做零训练审计更合理；但批准新算法之前，必须先让这些强基线真正接受公平检验。
